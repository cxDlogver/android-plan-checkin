# 结构完整性与语义完整性：通用最终验收契约

本规范适用于所有使用 requirements-state-graph 的需求分析运行，不针对某个项目或历史产物。**最终门禁同时要求结构完整性和语义完整性**；阶段性建模、局部检查及 HTML 观察不等于已通过最终门禁。

## 术语与不变量

- **真实起点**：在已确认范围内具有业务来源和合法初始化方式的状态；按功能可以存在多个起点，不强行创造全局根节点。
- **有效迁移**：有来源依据、行为与结果独立、且**存在至少一条从真实起点出发、所有相关条件成立、能够实际执行到该迁移并产生目标状态**的完整场景。
- **执行见证**：针对一条迁移提供入口、按顺序发生的全部前置操作及本迁移、具体合法数据、每步事件可触发／守卫成立／结果一致的依据。一个见证足以证明存在性，不要求覆盖全部输入组合。
- **完整有效边**：保留全部有效迁移（包括平行边、自环、回环与跨功能连接），而不是保留所有画出的边；不得因整理图形而丢失有效迁移。
- **结构衔接候选**：to(Ri)=from(Rj) 时导出的候选关系。它不能自动证明两个原子需求连续可执行；只有一条合法见证中出现相邻的两步，才能称其为有见证的连续执行关系。
- **语义未决**：缺少来源、前置条件或领域规则，尚无法判断是否合法。不能直接宣称有效，也不能将“找不到见证”自动等价于“已证明无效”。

## 结构完整性（全部适用）

1. 状态事实、迁移端点、事件、守卫、原子需求、功能、来源和 UI 引用合法且可定位。
2. 每条迁移恰有一个原子需求；两张图由唯一模型确定性生成。共享状态、不同连通部分、平行边和回环均按原有语义保存。
3. 状态抽象以可验收业务事实、可操作性或可观察结果为依据；行为等价的数据样本不拆成重复的状态或边。
4. 从来源提取的行为义务都有明确映射或处置。覆盖证明以来源条款／设计区域和相关迁移 ID 为单位；程序只能检查声明与引用的完整性，不能自称发现了全部未写入的需求。

## 语义完整性（全部适用）

1. **逐条有效迁移存在合法完整执行见证**：路径首节点为真实起点，前后状态连续，路径末步为被证明的迁移；场景数据、事件可触发性、守卫条件、必要权限／时间／数据约束及终态事实彼此一致。
2. 逐边审查必须同时考虑起点合法性、前置操作遗漏、状态抽象遗漏、守卫矛盾和结果矛盾。图连通性或一个 `guard=true` 字符串不能代替语义证明。
3. **逐来源反向检查有效迁移覆盖**：从已确认规则与 UI 行为审查遗漏的成功、拒绝、失败、取消、返回、重复、时间和跨功能分支；不同验收义务才拆分。
4. 结构候选衔接对中：有连续两步见证的标为 witnessed；确证条件不可兼容的记录 excluded + 依据；未定的保留 pending 并阻止正式发布。不能通过删除状态图的有效边来掩盖衔接冲突。
5. 旧版结构检查通过、达到固定轮数、AI 声称无新发现、文档有漂亮的可视化，都不是语义完整性证明。

## 无执行见证时的标准处置

按顺序检查并记录：①真实入口或业务初始事实是否遗漏；②是否缺前置操作／跨功能迁移；③源状态是否过度合并或缺少有意义的事实；④事件、守卫与时间／权限／数据约束是否写错；⑤目标结果是否矛盾。

- 有来源依据能修复：新增或修正状态／迁移／条件，保存 changes，原子需求同步修改，再次补漏、复审。
- 有依据证明不可能执行：**删除无效边及对应原子需求**，用 remove 记录原因、来源及退休 ID；重新生成双图及相关衔接；不要保留无效边以满足“完整边”。
- 无法从来源决定：登记 question 和 candidate，继续不依赖该决定的工作；正式有效边集合不得将其当作已证实内容，最终须由用户解决或明确移出范围。
- 等价：只保留改变行为或验收义务的有效分支；数量样例可归入同一迁移的多个验收例，不造重复边。

## 工作流与门禁分工

- **构建时**：每建模／修改独立迁移组即补执行见证并 checkpoint；新条件影响相邻边时重检；每轮同时记录正向与来源反向审查。
- **收敛时**：当前语义摘要下，逐节点十维审查、逐迁移执行见证、逐来源覆盖声明、候选衔接处置都完成，且无未处置的语义前沿。
- **程序检查**：验证端点存在、入口引用、路径逐步连通、场景及解释字段不空、见证引用、候选衔接分类及与路径一致性、覆盖条款引用和版本摘要；不会运行任意 guard 字符串，不声称能证明自然语言业务真实。
- **独立模型评审**：核对实际 PRD/UI、人工作答和场景事实，判断守卫是否真的可满足、路径是否合乎业务、目标事实是否正确、覆盖是否遗漏、等价与排除是否合理。评审报告必须覆盖当前全部迁移和来源覆盖项，且固定 semantic_feasibility 与 semantic_coverage 两项均通过；缺证为 inconclusive 而不是 passed。
- **最终发布**：STRUCTURE-001、FEASIBILITY-001、COVERAGE-001、CONTINUATION-001、独立评审、来源、审查、产物和人工确认全部通过才发布。结构与语义任何一方 pending/failed 均不得发布。

## 执行见证与覆盖声明的注意事项

单一业务操作可能有多项共同成立的验收断言，不拆为多条迁移。真实起点可以是领域建模边界内明确规定的初始化状态，但不得绕过范围内的必需操作直接“设置”中途状态。测试中的预置状态不能冒充正式路径。

见证只代表某一合法实例；同一状态存在不同历史、权限或数据时，不能从结构节点相同推断所有连续组合都成立。出现抽象混淆时先细化状态，不新建平行的人工真相图。

证明能力有边界：程序发现反例可失败；无法形式化求解的语义交给独立评审；**任何无法验证的断言不得因为存在字段就自动通过**。
