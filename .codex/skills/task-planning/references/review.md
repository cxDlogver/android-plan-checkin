# 人工审查 HTML

- requirementsReview 是有哈希绑定的输入。读取其中数据，与本轮状态、迁移、原子需求、需求图、真实起点和入口需求逐项核对；不一致先更新输入，不能静默替换。
- 复用原 HTML 的完整状态图、需求覆盖图、布局、中文文案、Canvas平移/缩放/拖拽/缩略图及详情。在同一个页面新增“测试图”，初始显示测试图。需求图和测试图使用同一组节点位置；切换后结构、入口和连线位置对应。不得维护第二套不一致的全量布局。
- 测试图为需求图的等价映射，仅新增待验收/失败/通过标注。每条有向连接只画一次，点击显示前后测试、衔接状态、后项条件、源路线和步次。状态边仍对应原需求；原有两个视图保持原意。
- 点击测试节点：条件、准备、步骤、功能预期、预期状态、视觉预期与UI原图/CSS、逐实例逐断言实际结果和证据槽、真实入口到当前测试的完整中文链路。链路按源覆盖路线前缀显示，终点只到当前项；条件冲突显式提示，不能当作执行证明。
- 不显示原始JSON和内部ID；无图不补设计，无实测显示待采集；只读HTML不记录通过。实测图和设计图区分。真实起点选择器支持多个真实入口，入口测试数量继承原需求图。
- 上游HTML不符合适配接口时拒绝导出，先实现显式适配与验证，不能退回另一套页面。HTML复用本身不等于交互验证：核验三视图节点/边/入口、切换位置、节点/箭头点击、拖拽缩放、多起点和证据展示。模拟Canvas明确标为模拟，浏览器未观察标NOT_TESTED。
