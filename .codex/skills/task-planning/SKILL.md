# 任务规划与验收设计

把需求分析转成开发任务和验收设计。读取 PRD、完整状态图、原子需求、需求衔接图及 UI 资料；调查仓库与存量代码。需求图是测试主图的结构来源，需求审查 HTML 是界面来源；现有代码是实现与回归风险证据，不能覆盖 PRD 或人工决策。

## 完成条件

- 每个范围内原子需求恰有一个主测试项；多条断言或参数实例归属于该项。回归范围以用户确认为准；暂不考虑回归时不生成回归项或回归入口。需要回归时单列扩展，必须有修改点→受影响调用/数据→既有行为→测试依据。
- 每项有准备条件、操作、预期功能、预期状态、来源；视觉仅使用已有 UI 依据。预期与实测结论分开，初始全部待验收。
- 状态图保留输入的全部状态和边。测试主图与需求图节点、边、入口一一对应；使用次数为元数据，同一有向连接只画一次。继承需求路线与条件检查，不能为排路线重写主图或把孤立节点提升为起点。
- 实现 Plan 基于读过的代码，列出复用/修改位置、依赖、完成条件、对应测试与必要检查。开发仅必要静态检查和单元测试；全部开发完成后才执行完整产品验收。
- 确定性门禁检查身份、映射、覆盖、条件、证据及阶段；独立评审检查语义。两者通过后再提交最终人工确认，不把结构通过当作业务或视觉通过。

## 执行

1. **初始化。** 先读 [contract.md](references/contract.md)，用 scripts/planning.py init 声明产物与检查条件。只创建 _process/planning.json；持续维护当前文件，不创建进度快照、历史版本或额外版本目录。
2. **确认范围。** 读取输入及来源，复用已确认人工作答。只澄清会改变范围、验收平台或目标的歧义，不让 AI 决定新业务。中途未知项进入 issues，继续独立工作，最终集中确认。未批准的上游分析可用于草案，不能伪装成开发基线。
3. **调查代码。** 查入口、依赖、状态/数据流、共享组件及已有测试，登记读过的行和摘要。无代码时如实记录，不虚构回归项。区分源码证据、差异候选和运行验证。
4. **写测试与计划。** 按 [test-design.md](references/test-design.md) 填数据、断言、回归理由、任务与检查。完成一个功能或影响链就保存；工作产物本身持续维护，不另记进度档案。
5. **映射图与路线。** 读 [routes.md](references/routes.md)。确定性映射输入需求图和已有路线，不重新优化。条件冲突、未验证和准备缺口原样暴露；结构最短不代表可以执行。另行请求路线优化时，作为独立候选，不改测试主图。
6. **生成审查产物。** build 同源生成 JSON、两个 Markdown 和 HTML；check 校验当前内容并保留诊断。HTML 复用已绑定的需求审查 HTML，在原视图上增加测试图；按 [review.md](references/review.md) 核验。不要修改上游需求以迎合规划器。
7. **独立评审。** 交给独立评审上下文检查来源忠实性、断言可判定性、存量影响、路线可执行性、计划可实施性、阶段/证据门禁、HTML 可读性。报告绑定 planningDigest，失败修复复审；工具不可用标 NOT_TESTED。模拟交互不能冒充真实浏览器观察。
8. **交付。** 展示草案及待决项；机械检查、独立评审、资料就绪均通过后才请求正式规划确认。保存真实人工作答和摘要后才能 advance development。未通过时交付标注的草案与阻塞原因，不自行确认。

## 后续消费边界

本 Skill 默认只规划。另行授权开发后按 Plan 维护任务和静态/单测证据，不在开发中启动浏览器或模拟器进行产品验收。全部任务完成、必要检查通过后，advance acceptance 才允许登记产品实测。使用 record 保存功能/视觉逐断言结果和证据；重复经过不自动通过，每个实例均须观察。失败修复使相关旧证据失效，重验受影响链路。

脚本只约束正常命令通道，不能证明模型独立性、人工作答真实性或阻止绕过文件写入，不称为系统权限级硬门禁。
