# 迁移可执行性与验收

## 三个不同的证明义务

1. 状态可达：从至少一个有来源的真实入口，存在到达该状态的合法路径。
2. 迁移可执行：从真实入口到达该边的起态后，累积条件允许执行这条边，且执行结果满足终态事实。仅证明两端状态分别可达不够。
3. 路线可执行：从该段入口条件出发，按顺序执行全部迁移，所有步骤共享前面产生的上下文。每条边分别可执行，不保证任意排列或衔接都能执行。

同一迁移有多个已声明的析取 case 时，每个 case 都必须至少有一个从真实入口执行该分支的见证；只固定见证最后一步的 case，前缀可使用任意合法分支。此义务不要求覆盖多值枚举的所有笛卡尔积，也不将分支覆盖加入需求访问次数的优化目标。

三者均须检查。完整状态图保留全部有依据的合法业务边；未选入覆盖路线不构成删边理由。候选关系只表示状态结构相接，不能直接充当有效执行顺序。不得以节点数量、入出度、无孤立点或最短到达链路覆盖替代逐边检查。

## 模型约束

pathContext 是原文条件的有限抽象。共享状态隐藏了来源、对象类型、只读资格、记录方式或数据是否存在等事实时，补充有来源的上下文或细分状态。stateConstraints 按状态 ID 保存 requires、sourceRefs 和 reason，表达该状态必然成立的事实；来源必须属于该状态。每次进入状态、离开状态和真实入口初始化均应用约束。不能把“全局无计划”与“当天无执行项”混为同一个条件。

所有 case 效果同时生效：requires 先限制旧上下文；setFrom 总是复制本次效果执行前的值，包括同时赋值或交换；set、forget、setFrom 不能重复写同一目标。保留关联值的独立分支，不把多个相关对象合并成任意笛卡尔积。导航与重启不得无依据改变持久数据。读取或返回只重新展示既有事实：若“结果为空／非空”是进入目标分支的条件，应编码为 requires；不能把这项条件写成 set，在没有真实写入、选日或对象变化时凭空制造空集合。真实写入引起的变化应由对应写入成功迁移表达，失败与取消保留旧值。

逐条核对中文 guard、目标 facts、验收 then 与机器约束一致。程序只证明已编码有限域，不能认证任意自然语言谓词、具体日期、真实集合成员或来源解释。未知规则保留待决；不通过扩大枚举、清除约束、添加假入口或伪造赋值获得通过。

## 确定性计算

scripts/feasibility.py 对每条迁移从目标反向计算有限域前像，以稳定 A* 搜索到真实入口：当前已走逆向长度为代价，从任一入口到当前节点的无条件结构最短距离为一致且不高估的启发值。该启发值只调整展开顺序，不放宽任何条件。目标包括该迁移本身；同状态上已有更短且覆盖更广的前置条件可支配后续搜索。找到后保存真实入口、初始条件、完整迁移序列、所选 case，并用独立方向的正向执行器重放。路径长度是执行目标边所需的最少迁移数。

结果分为：finite_domain_passed（已编码条件通过）、no_guard_constraints（无附加条件）、structure_only（仅结构可达）、infeasible（穷尽该抽象后无合法路径）、incomplete（资源限制未完成）。后两者不可混用；structure_only 不作为条件通过。state-graph.json 的 transitionValidation 与模型摘要绑定，恰覆盖所有当前迁移，以及每条迁移的全部当前 case 索引；caseResults 与 caseCounts 也须验证摘要、状态枚举、计数和末步 case。不新增独立的根目录过程报告。

FEASIBILITY-001 消费逐边及逐 case 证据：出现已证明无路的迁移则失败，未编码或未完成则待完成。路径证据须从合法入口开始、逐步连续、结束于被验证的边，并满足每步条件和状态约束；手填通过无效。

## 发现问题后的处理

回查精确 PRD/UI 条款及已确认答复，区分漏掉合法进入方式、状态抽象混淆、条件编码错误与无来源的机械组合。修复有依据的模型错误；错误候选从当前正式模型移除，在当前 rounds 留下原因。资料不足以确定的保留候选和待决，不替用户选业务答案。只有来源支持的缺口才能补边，不为了通过检查新增功能。

修改后重算全部状态链路、逐边证据及覆盖路线，更新同一套产物。旧摘要的审查及确认失效，不能替换摘要冒充重新审查。

## 验收证据

- 确定性：全部状态与边集合一致；每边入口见证有效；全路线逐步重放；用边和次数从路线重新计算；无未覆盖项、冲突或未完成项时才可通过相应门禁。
- 算法回归：用独立的具体状态穷举 BFS 比较小图的可执行边集合和最短长度；涵盖多入口、互斥条件、回环、目标不变量、同时复制/交换、析取相关性、资源中断与篡改证据。
- 独立模型：核对机器抽象是否忠实原文、条件是否遗漏、初始数据能否准备、保留边是否有独立义务、被移除边是否确实错误，及 HTML 的中文可理解性。不能用程序 PASS 代替。
- 产品验收：本阶段只审需求模型，不把条件证明写成应用功能测试通过；每项需求仍保留来源支持的功能、视觉及判定标准。真实实现测试由后续阶段执行。
