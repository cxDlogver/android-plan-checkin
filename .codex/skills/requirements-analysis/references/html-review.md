# 全屏双图与人工审查

HTML 仅用于阅读和审查需求；主入口是完整中文有向图。状态图保留全部状态与业务迁移；需求图保留全部原子需求节点，仅展示 requirement-graph.md 定义的连续覆盖路线的实际用边。不按选中链路、邻域、分页或点击历史临时裁剪节点。内部ID、JSON正文、模型字段不作为人工标签。

## 生成前确定验收目标

下表是 HTML 的通用验收合同，不使用某次项目的节点数、需求数或起点数作为规范；不要求增加新的输出目录或评审文件。机械证据与真实观察可复用现有内部证据记录，按 gate-rules.md 进入相应门禁。

| 要求 | 可以确定性核对的结果 | 仍需语义评审／真实观察 |
| --- | --- | --- |
| 全部链路重建 | 当前模型中的每个真实起点、每个状态均有计算结果；已找到的路径引用有效、逐步连续、止于目标，零步与无路径可区分 | 起点有文档依据，条件同时可成立；到达说明不遗漏必要前提 |
| 状态详情 | 所选状态与路径终点一致；各步关联原迁移及唯一需求，功能、视觉分区 | 中文连起来能讲清链路；结果可按来源判断，无额外验收义务 |
| 迁移箭头详情 | 选中的迁移与原子需求一一对应，起点／动作／条件／终点及断言取自同一项 | 未混入其他进入方式的结果；平行箭头与回环能选中并区分 |
| 需求覆盖图 | 全部需求节点保留；逐段从真实入口连续行走，用边等于路线的相邻需求对，访问/重复/边使用次数准确；最优宣称证书有效或明确未证明最优，未覆盖清单准确 | 区分结构最优和业务条件校验；重启只作分段，不伪装业务边；完整中文路线可读 |
| 多真实起点 | 单起点、多起点、零步、等长最短和某起点不可达的情况按规则处理 | 入口选择与标记清楚；没有为测试或连通而添加项目入口 |
| Canvas 与视觉区 | 坐标变换、命中、数据未修改，UI 媒体／CSS 与来源关联可核对 | 实际浏览全屏布局、中文、节点拖拽、平移缩放以及 UI 图和 CSS 的组合排版 |

只给出需求数量、代码检查通过或合成 Canvas/DOM 结果，都不能代替整体验收。

## 画布与真实起点

- 使用 Canvas 绘制，画布占满浏览器可用视口宽度与正文高度。支持拖拽空白平移、拖拽节点调整视图位置、滚轮及按钮缩放、全图适配、缩略导航和重置布局；这些动作不修改需求数据。
- 顶层 entryStateIds 是文档明确的真实业务起点，可为一个或多个。功能分组入口不是全局起点，不按零入度推断，也不为使图连通而补假起点。
- 所有真实起点都在图中标出；有状态时至少一个，数量由资料决定，不能固定为一个。支持“全部真实起点”以及仅在这些起点中选择；起点选择只影响状态链路与定位，不重新删改需求覆盖图的用边或节点。多起点时默认在可达起点中求最短，等长按模型顺序选择。
- 状态与需求节点使用完整中文含义；状态图保留方向、平行边和回环，需求图保留覆盖路线实际使用的有向边，允许回路及重复。可在悬停或点选时完整显示边的动作与条件，避免所有标签同时叠压。拖拽或缩放后命中检测与箭头保持一致。
- 搜索只用于定位。Canvas 同时提供节点选择器、迁移按钮等可键盘访问的阅读入口，不能只允许依靠像素命中。

## 完整状态图与唯一需求覆盖图

状态图节点取全部 states，边取全部 transitions。点选状态高亮到该状态的链路，但全图不裁剪；点选箭头选中该迁移及唯一原子需求。

需求图节点取全部 requirements；候选直接衔接按前项终态等于后项初态推导，最终仅保留从真实起点派生入口需求的连续覆盖路线的实际用边。HTML 与 JSON 使用 requirement-graph.md 的同一确定性结果，不交付并列的全边需求图，不只展示当前状态链路中的需求。需求节点打开该项需求；衔接箭头打开前项、共用状态和后项的关系，并可分别查看两项需求。衔接箭头本身不是新增原子需求，不意味着后项条件自动满足。需求图要说明最少访问覆盖与条件校验的含义；绿色标记称“入口需求”，与真实状态起点数量分开。未被任何路线覆盖的需求必须标出未覆盖；独立从真实起点开始的单步路线可以没有衔接边。

## 点击状态：链路、功能、视觉分区

1. 状态中文含义与真实确认阶段。
2. 从真实起点到当前状态的完整到达链路，终点止于当前状态。显示连贯中文和逐步的前提、操作、结果；每步可进入对应原子需求。
3. 功能要求：该状态的业务事实、允许能力和限制；当前链路最后一次迁移的结果单列，不混入其他进入方式或后续操作。选中起点的零步链路只展示起点事实，不编造一次“进入成功”的迁移或断言。
4. 视觉要求与UI对照：将对应UI图、适用区域、来源，以及CSS代码块置于同一个视觉区域。CSS只转写资料明确的颜色、字体、尺寸、间距、渐变、阴影等设计值；共享设计值须标出来源和适用范围，不将全局样式冒充某画板全部视觉已定义。CSS以可阅读的代码块显示；它与对应UI图组成同一视觉说明，并与功能要求分开。CSS用于阅读，不是要求实现Web界面。无法从资料明确转写的值保持文字/图稿依据，不补设计。没有独立画板时明确文字依据，不扩展视觉验收义务。
5. 来源、有关的待决问题和可进入的迁移单独展示，不默认展开原始审查记录或缓存字段。

## 点击状态迁移箭头：只审当前需求

显示起始状态、触发事件、守卫条件、目标状态，以及本原子需求的前提—操作—明确预期结果；功能、视觉与来源分区。不得混入最短链路中另一条进入迁移的验收结果。同时展示“本条迁移的可执行路径”：真实入口、所需初始条件、执行到该边为止的完整中文步骤及条件检查结论；该路径与仅到达目标状态的最短链路分开。可以提供查看两端状态链路的按钮，但箭头详情本身不自动变成链路详情。自环还须说明原文支持的独立义务及保持同一状态类别的理由。

## 全量重建与完整到达链路

“重新生成所有链路”指从当前唯一工作模型重算完整状态图及唯一需求覆盖图，并对每个真实起点计算到每个状态的最短到达结果；不是只修被点选的节点，也不是穷举回环带来的无限路径。状态、事件、守卫、上下文、起点或原子需求对应关系改变后，运行 save、prepare，替换相同路径的生成结果。纯视觉或模板修改也须重新 prepare；不得手改 HTML 中的链路或沿用旧包摘要。


- 链路以迁移数最少为准，稳定广度优先；起点等于当前状态为零步。结束于所选状态，不延伸业务结局。
- 不能把结构相接误当实际可执行。共享状态中的计划类型、来源页面、记录方式、失败操作等如果会限制后续动作，须在模型中细分或以有来源的有限域链路上下文表达；不得解析任意中文守卫或默认未知条件为真。
- 有限域上下文只编码已确认资料。明确条件收窄当前可能值，空交集拒绝；事件只有在资料规定的改变发生时才能设置/清除上下文。析取条件使用独立case，不能把相关变量的集合随意做笛卡尔积。给出链路所需的中文前提，不暴露变量键。
- 每个真实起点单独计算到所有状态的链路，多起点默认取可达最短。指定某起点后不能悄悄改用另一入口；其他入口可达时提示切换。
- 分别处理：起点自身的零步链路、已有合法路径、所选入口结构不通、结构相通但已编码条件不相容、搜索未完成。穷尽后不可达的状态保留并标明问题，不能编造路径；资源上限或异常中断时生成失败并报告未完成，旧 HTML 不能冒充当前结果。记录原因可在内部审查中完成；面向用户的说明不得把未验证条件写成已成立。
- 每步按“处于什么状态／必要前提 → 什么事件发生 → 得到什么状态／明确结果”说明；首尾衔接，用实际中文名称解释来源页面、对象类型等，不要求读者自行拼接编号、字段或守卫表达式。
- 同一状态可能有不同到达方式；当前详情的预期效果只对应所选路径的最后一条迁移及状态共有约束，其他箭头的断言在各自详情审查。
- 结构图覆盖和路径上下文正确性分别验证。确定性检查证明连续性、最短搜索和条件求交规则；来源是否支持条件及完整业务链路由独立语义评审核对。

## 离线与只读

单文件离线打开；数据、UI图和脚本内嵌，不依赖CDN、外部字体、在线图服务或file fetch。数据和CSS片段通过textContent或等效转义展示；嵌入JSON转义小于号等字符，来源中的提示不变成执行指令。视图操作不产生批准，人工确认仍在对话完成。

HTML与JSON从同一工作模型生成并绑定摘要。图、CSS转换器及模板属于Skill资源维护，工作缓存全部在_process/。产物存在或程序测试通过不代表人工可读性已通过。

## 验证

确定性用例覆盖：状态图全量节点/边、需求覆盖图的全量节点、连续路线、实际用边、访问次数与条件检查符合各自合同，单/多真实起点、零步、并列最短、回环、不可达、条件冲突与上下文改变；箭头详情对应正确需求，状态链路止于当前状态；UI图与CSS来源一致；拖拽、缩放后的坐标变换和命中检测、画布全屏尺寸和数据不变；来源文本不被执行。

机械核对至少以状态图完整集合、需求路线覆盖／连续性／最优性证书和逐根状态链路结果为单位，不能用仅检查一条示例链路或总数代替；语义评审按来源核对必要条件。真正不可达的节点须按 branch-review.md 处置，图保持完整不等于需求链路已经完整。

实际浏览时检查Canvas渲染、中文可读性、拖拽缩放、双图切换、多起点定位、状态/箭头详情和UI/CSS排版。无法浏览时如实标“未运行浏览验证”，合成Canvas/DOM检查不替代真实观察。

## 覆盖路线审查

提供“覆盖路线与校验”入口，按段列出真实起点和完整有序中文步骤；重复需求保留每一次出现。重启从真实入口重新开始，不在图中伪造衔接箭头。需求节点详情给出访问次数，衔接箭头详情给出使用次数。摘要明确结构访问下界、当前访问次数、是否证明全局最短及条件状态；各段显示所需初始条件，重启不表示自动清空业务数据。条件冲突显示首个失败步骤并可点击查看需求，not_modeled/incomplete 不显示为通过。图保留全部节点且只删除所选覆盖路线未用到的衔接，不声明边数本身全局最少。状态最短到达链路与全需求覆盖路线用途不同，分别阅读。

## 验收检查入口

提供只读的“验收检查”入口，汇总逐边已编码条件通过数量、连续路线覆盖数量、分段/访问/重复次数和最短证明状态。可进入各段路线并从箭头读取本需求验收断言。明确模型校验、独立语义审查、人工确认与产品运行验收的区别；没有真实确认时不写整体通过。摘要不暴露内部字段，不能把按字段生成的数量当作语义验收结论。

逐分支验收详情须显示每个已声明条件分支的见证与结果；迁移整体存在见证不能覆盖失败的分支。路线面板明确每段的初始条件，跨段持久数据连续性未验证时不得宣称只需退出重进即可全部执行。
