# 需求覆盖图：条件可行路线、访问优化及用边

## 验收目标与范围

只交付一份 requirement-graph.json，HTML 展示同一图。全部原子需求节点保留；有向边恰为所选连续覆盖路线中相邻需求的直接衔接，重复使用同一边时合并绘制并记录 usageCount。允许回路、重复节点和重复边。起点由文档的 entryStateIds 决定，不从零入度、功能局部入口或搜索顺序推断。

优化目标是覆盖所有需求所需的总需求访问次数，每执行一次需求计 1，包含重复。不同需求数是覆盖义务，不是可减少的目标。保留边数、重启次数与总访问次数是不同指标；不声称用边集合在全部等长路线中也是边数最少。每条保留边都服务所选路线，但不声称它在所有最优解中都不可替代。

模型 requirementTraversal.restartPolicy 为 none（省略时默认）或 documented_entries。后者必须有非空 authorization，引用真实用户决定或资料位置；表示允许结束当前段后重新从任一已声明真实起点开始，重启不计需求访问次数。不能把这种分析操作改写为新业务迁移，也不能默认它重置业务数据。更改成本或重启语义须先明确口径，再修改求解器，不能静默忽略配置。

## 入口、完整关系与连续性

每条状态迁移对应一个需求。前项终态等于后项初态时才有候选直接衔接；候选图在计算过程中重建，不另外输出全边需求图。入口需求是从真实状态起点出发的迁移，一处真实起点可能有多项入口需求。

每段路线从真实状态起点开始；相邻迁移必须首尾相接。BFS/DFS 的出队顺序、回溯栈和父指针不构成执行路线；只有真实迁移才能连接段内步骤。重启只出现在路线分段之间，不画成前项需求到入口需求的业务箭头。状态图始终保留全部业务边。先完整求解路线，后投影用边，不先删成森林再寻找返回路径。

不可达需求仍输出并标为未覆盖；无合法连续覆盖方案时如实标 infeasible。未执行的搜索或资源中断不能标为无解。无重启时，即使每个节点分别可达，也可能无法单次覆盖多个终点。

## 确定性算法

一需求等于一状态边，因此需求节点覆盖可转换为状态边覆盖。普通任意节点图不具备此等价关系。

1. 原有迁移下界为 1、成本为 1。先从真实起点求结构可达集合；不可达部分保留未覆盖，不进入“全部覆盖”的宣称。
2. 允许重启时，在辅助计算网络使用虚拟汇集点：状态到汇集点、汇集点到真实入口的边下界为 0，主要成本为 0。按原有迁移的弱连通分量求解，每个分量内部必需边连通且有真实入口。虚拟点和边不导出为业务节点/箭头。
3. 将全部原有边先走一次，按出度减入度计算不平衡。用整数最小费用流，寻找使进出次数平衡且重复迁移成本最小的增量。脚本使用逐次最短增广路，残量网络用 Bellman–Ford，支持平行边与自环；平局按稳定状态/迁移 ID 及文档入口顺序决定。次目标减少辅助重启边，整数权重的主目标倍率须大于全部可能重启费用，不能改变访问次数的最优值。
4. 不允许重启时，对声明起点及可能终点组合求解开放路线：加入一次性终点到起点的辅助闭合边，该边不得重复；取所有可行组合中需求访问次数最少者。不可行组合跳过，全部失败才标结构无解。
5. 按流量复制原有迁移，用 Hierholzer 生成欧拉序列。移除辅助闭合边或按重启边分段；每段只留下原有迁移和对应需求的有序序列。
6. 投影每段相邻需求对，合并相同直接衔接并统计 usageCount；不得跨分段补箭头。同一输入产生相同结果，输出不受迁移数组的排列变化影响。

此方法的最优性限于结构模型。必需边连通是平衡后能生成单个欧拉序列的关键；不能把最小费用流直接套到任意不连通必需边子集而忽略连接代价。原有弱分量之间没有业务边，明确允许重启时才可分段覆盖。

## 条件校验与门禁

先按 feasibility.md 验证每条迁移均有真实入口见证。按 entryContexts 初始化，应用 stateConstraints，逐步重放 requires、set、forget、setFrom；一步空交集就是冲突，资源限制是 incomplete，非平凡守卫未编码是 not_modeled。只有 finite_domain_passed 或 no_guard_constraints 是条件通过；这不证明未编码的业务条件。

结构最优解只提供访问次数下界。如果该解所有条件通过，则它也达到约束问题的下界；否则不能把冲突路线作为覆盖计划。当前实现采用确定性的可行方案：以每条边的最短合法见证为候选，优先选择新增覆盖收益较高的路径，沿当前状态尝试可重放的见证后缀；不能继续且明确允许重启时，另起真实入口段。删除完全被其他段覆盖的冗余整段，不删去必要的进入前缀。重新重放所有保留段，再投影实际用边。

此方案是启发式，status=feasible 只表示在已编码条件下完整覆盖，optimality=not_proven；不是全局最短，也不是无解证明。未覆盖则 partial；无重启时不能把其他独立入口见证私接成连续路线。若要证明有条件的全局最少访问，可在“状态＋具体有限域赋值＋已覆盖迁移集合”上求最短路，或提供等价精确约束求解证书；资源耗尽保留未证明状态，不能改名为最优。

每段保存可重放的初始条件和 case 选择。重启仅是路线分段，不是业务数据重置；前一段终态与后一段初始数据不一致时，按独立场景准备条件阅读，不能伪装成只退出重进即可执行。实际数据是否能准备及中文前提是否充分，由来源与独立语义评审确认。

FEASIBILITY-001 检查每条迁移的合法入口见证。LINK-001 检查全部需求覆盖、真实入口、逐步连续、条件重放、用边精确投影及计数；有最优宣称再检查相应证书，不强迫启发式伪造最优结论。已知冲突、未编码或未完成不能通过。未知源语义交独立评审，不能被程序通过覆盖。

## 结构化结果

- nodes：全部原子需求及原属性。
- edges：原候选 continuation 边及 usageCount；边 ID 为 C: 加前后需求 ID 的紧凑 JSON 二元组。
- reduction：kind=minimum_visit_route_support 或 feasible_route_support、algorithm、entryRequirementIds、unreachableRequirementIds、uncoveredRequirementIds、原始/保留/移除边数。
- traversal：objective、restartPolicy、restartCost、optimalityScope（structure_only/finite_domain_feasibility）、status（optimal/feasible/partial/infeasible）、totalVisits、repeatedVisits、visitCounts、routes 和 certificate。
- routes[]：entryStateId、transitionIds、requirementIds（按实际顺序，保留重复）、contextCheck。路线分段就是重启边界，不能隐藏为一条连续业务路线。
- 条件可行方案另含 algorithm=witness_cover、optimality=not_proven、lowerBoundVisits、transitionValidation 摘要；certificate.globalMinimumProven=false。routes[].contextCheck 保存初始条件、所选 case 和重放结果，供下游直接复用。
- certificate：结构最优时为平衡流量及残量无负环结论；验证器从实际路线重新构造下界残量网络检查，不信任手填布尔值。无重启模式的生成器与验证器均逐起点/终点枚举核对全局最优，残量证书仅证明所选端点下的流量最优；infeasible 声明也必须重算可行性，不能仅凭路线为空接受无解。

所有节点都有覆盖结果；不可达与可达但不能连续覆盖必须区分。空路线不得声明覆盖非空需求集。totalVisits 等于所有分段的长度和，repeatedVisits 等于总访问次数减实际覆盖的不同需求数；完整覆盖时后者就是全部需求数。

## HTML 与验证

HTML 名称使用“需求覆盖图”，显示节点/用边数量、访问/重复次数和结构/条件状态。点击箭头显示前后需求、共用状态、使用次数；提供“覆盖路线与校验”入口按段展示起点、完整中文步骤和首个条件冲突。只显示中文，不暴露原始 ID、JSON 或内部字段。节点保留拖拽、平移缩放；未覆盖节点单独标出。状态详情仍展示完整状态图计算的、止于当前状态的最短到达链路，与覆盖全部需求的路线分别说明。

scripts/requirement_graph.py 是唯一生成入口，JSON 与 HTML 共用其结果。verify_coverage 从路线重建实际用边、计数、上下文结果和残量证书。测试使用独立的“当前位置＋已覆盖边集合”0/1 最短路作小图最优值 oracle，覆盖回路、自环、平行边、多起点、重复主干、终点分叉、不可达、未授权重启、输入顺序稳定和产物篡改。

状态/迁移/入口/条件/重启政策改变后全量重建；同路径更新当前文件与 manifest，旧评审/确认按摘要失效。不得创建历史快照或并列版本。
