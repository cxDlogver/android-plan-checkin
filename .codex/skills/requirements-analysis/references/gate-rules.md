# 固定验收门禁

门禁对应本任务的来源、人工范围确认、模型结构、图间关系、循环审查、待决处置、独立语义评审、观察产物和最终人工确认。其固定规则和 rubric 由 assets/gate-contract.json 承载。不得按本轮难易删规则或补造通过记录。init 全 pending；assert 重算实际检查，旧 checks 的 passed 不作依据。失败含 rule_id、failed_object、expected、actual、evidence_ref、failure_reason、repair_from、recheck_from。

## 机械规则

下表适用于最终整体确认／发布。prepare 草案只检查基本结构，可供集中澄清，但不代表通过。修复后重跑该项及依赖门禁。

| ID / 类型 | 通过条件与必需证据 | 修复／重查起点 |
| --- | --- | --- |
| INIT-001 / 程序 | _process/ 合同、模板摘要、完整规则集与工作文件正确 | 固定模板初始化或在当前目录显式迁移 |
| SOURCE-001 / 程序 | 每来源精确定位、读取范围、真实缓存、SHA256、可选图片预览摘要匹配 | 补读资料、保存证据，再查来源与语义 |
| SCOPE-001 / 程序＋人 | 真实初始确认绑定当前 scopeDigest；相同范围内容更新后仍有效 | 人工确认新范围、保存决定，再分析 |
| MODEL-001 / 程序 | schemaVersion=2，结构、类型、枚举、全局起点非空且引用有效、自环 selfLoopEvidence、可选有限域 pathContext 的覆盖/枚举/操作及来源引用合法、来源／UI／功能引用合法 | 修模型、全量验证 |
| FEASIBILITY-001 / 程序 | 全部迁移及其每个已声明 case 都有真实入口到目标边／分支的有限域见证，正向重放有效；无 infeasible、structure_only 或 incomplete；不等同原文语义及产品验收 | 按 feasibility.md 回查来源、修模型并全量重建 |
| LINK-001 / 程序 | 迁移需求双向一一对应；全部需求保留，路线从真实入口逐步连续且无未覆盖需求；用边精确等于段内相邻对，次数正确；最优宣称须有对应证书，启发式必须标 not_proven；各段条件结果为 finite_domain_passed 或 no_guard_constraints，边 ID 无歧义且唯一 | 修迁移／需求，同源重导出 |
| PROCESS-001 / 程序 | 当前模型/状态摘要一致，读取证据和逐节点审查已保存，待审队列空 | 修复当前内容并 save，补做缺失分析，不补造过程 |
| AUDIT-001 / 程序 | 至少一次建模／审查后，当前摘要闭合轮覆盖全状态×十维，无变化／前沿；phase=review_ready 或 confirmed | 从缺节点、轮次或变更后重审 |
| QUESTION-001 / 程序＋人 | 所有开放问题处置、候选转有据草案；affectedIds/questionIds 一致 | 最终集中问答、修订、闭合与评审 |
| MODEL-REVIEW-001 / 程序消费LLM | 真实独立上下文、完整输入、当前语义／包摘要、实体全覆盖、八项 passed、证据可校验、无开放发现 | 修复并独立复审；缺证补证重审 |
| ARTIFACT-001 / 程序 | 根目录仅含已声明的消费/审查产物；唯一过程目录为 _process/；根目录导出与工作模型、内嵌图片及 manifest 逐份一致 | 从 _process/ 工作模型 prepare 更新根目录交付 |
| APPROVAL-001 / 程序＋人 | 真实最终回复，语义／包／报告摘要和全部实体覆盖一致 | 双层通过后取得当前内容整体确认 |

HTML 的具体可观察条件统一见 [html-review.md 的验收目标](html-review.md)。状态图完整集合、需求覆盖图的连续路线／实际用边／访问次数／最优证书与逐根状态链路计算使用确定性生成和测试核对；当前正常通道的 ARTIFACT-001 核对同源导出与文件摘要，MODEL-001 核对模型结构，FEASIBILITY-001 逐边检查真实入口见证，LINK-001 消费 requirement_graph.py 的覆盖校验并拒绝未覆盖需求及路线条件冲突、未编码或未完成。这些程序检查不自动认证所有中文守卫可满足、全部功能链路已覆盖或实际画布可读；相应结论必须有独立评审与真实观察，不能把文档要求写成已实现的运行时强制门禁。

程序核对报告结构、声明、对象和证据一致性，不替代模型的语义判断。人工作答和独立性真实性由执行 AI 核对实际会话，程序不能认证。

## 独立模型 rubric

| criterion_id | 开放性验收 |
| --- | --- |
| source_consistency | 原文、范围、需求事实一致；附件指令未升级为要求 |
| branch_meaning | 新分支有文档内的独立义务；每条自环逐项核实精确来源、独立响应／约束、同一状态理由；同义分支未重复计数，不按控件×状态机械扩展 |
| atomicity | 一迁移为独立行为；结果和共同断言完整 |
| guards_and_complements | 条件、合法域、反面与边界有据；链路中来源、类型、操作方式等上下文连续，未用互斥条件拼接假路径，未知未补默认值；逐边见证符合来源，状态事实与效果一致，重启不会默认清空数据 |
| ui_mapping | 画板、文字规定与状态对应；不把文字引用当具体视觉已定稿，也不把未要求的视觉细节变成缺口 |
| unresolved_decisions | 未定义未隐含选定；人工决定与影响相符 |
| convergence | 最后变更后全量复审；全部真实起点及逐节点到达结果已核对，应可进入状态的断链和条件冲突已处置；最短路径未覆盖的迁移仍有分支审查；限定范围 |
| html_observation | 实际浏览全屏Canvas完整状态图及唯一需求覆盖图，全部真实起点可定位且支持多起点；点击状态显示保留条件上下文且止于当前状态的最短到达链路；点击状态箭头显示唯一需求，衔接箭头显示前后需求关系与使用次数，覆盖路线显示完整中文步骤、重启分段和条件校验；功能、UI图及有来源的CSS分区清晰；无内部ID、JSON正文或字段结构；拖拽、平移缩放、命中与导航有效，有观察证据 |

branch_meaning 的评审证据须列出当前全部自环及逐条结论。仅列数量、复述边或复制同一套理由不算审查；不支持的条目先修复，不能用结构通过覆盖。

报告绑定精确包摘要，HTML 变化也使报告过期。failed 修复重审；inconclusive、输入截断、无独立上下文或 HTML 未运行不能通过。最终待决澄清可以发生，但双层通过前不请求整体验收。

## 计算结果

- 机械规则或模型报告有确定失败：failed，模型通过不能覆盖。
- 必需检查／报告／证据未完成：pending。
- 除 APPROVAL-001 外全 passed：awaiting_final_confirmation，才允许请求整体确认。
- 全 passed：passed，publish 才能整包发布。

输出存在不等于通过；assert 不是运行时 Hook，不能防止绕过命令直接改文件。不要配置全局 Hook 或声称权限级强制。
