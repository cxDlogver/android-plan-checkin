# 失败定位、修复与继续验收

## 1. 进入修复

当前访问未通过时，先登记失败或阻塞、保存现场并同步合同和 HTML，停止路径。工具登记 diagnosing，begin/next/finish 不再放行；定位之前不能反复重跑整图或进入后续用例。

分析实际输入、初态、预期来源、操作与实际终态，以及数据、Mock、脚本和环境。repair-open 登记 cause category、可读原因、实际证据、受影响用例及必要规范来源。分类应有依据，不把所有不一致都归为代码问题。

## 2. 按原因修复

| 原因 | 修复入口与完成条件 |
| --- | --- |
| code：实现不符合合同 | 回代码执行 Skill，修复对应代码并完成当前版静态检查；记录变更文件及摘要 |
| test-case：预期、数据规范或证明方式不符合正式规范 | 依据任务规划的用例规范及原 PRD、授权 UI 或规范，仅修正验收副本中的 Test Case，复审初态/动作/终态、数据/Mock、验收充分性和来源 |
| harness：驱动、断言、取证或提交脚本错误 | 修复脚本或取证链路，核对独立预期和真实操作不被替换，保留原失败 |
| environment：宿主、依赖、数据准备或 Mock 恢复不满足前提 | 补足真实前提或修复边界，提供实际就绪与恢复证据；无法解决时保持阻塞 |

代码与验收预期都可能有问题，应分别说明影响范围并依次修复。Test Case 中被授权的动态数据与 Mock 准备规则也属于用例规范；运行时取值或依赖故障按其实际原因归类。

## 3. 修改预期的依据

只有独立正式来源能够说明原预期不符合规范时，才能进入 test-case 修复。登记 standardSources 的 path、sha256、locator，以及原预期与条款冲突的原因。实际截图、被测输出、断言失败本身或错误用例不能作为修改规范的授权。

新用例必须仍映射同一正式需求迁移，检查方法足以证明原事实；不删掉真实需求、降低标准或改动 PRD/UI 事实来适配实现。修复报告保留原定义与修正后的定义、来源依据和审查结论。需求本身不明确时返回需求澄清，未回答前保持阻塞。

更新预期后核对用例结构、来源、迁移一致性、数据、Mock、证明充分性及受影响范围；记录实际复核证据。验收不得直接修改任务规划原件。若变化影响逻辑路径、环境能力、任务范围或需要更新原规划基线，先返回相应规划阶段另行处理；审查新基线后再迁移验收副本，不静默重新绑定历史结果。

## 4. 关闭修复并继续

repair-close 提交 observation、evidence、changedFiles。复核报告采用 assertion-report，target=repair:<原失败attemptId>，保留应达到的修复要求、实际修复和 verdict。代码修复还需 implementation.json 表明当前静态检查通过；用例修复需正式来源有效、修改范围已复核，并保留新旧定义摘要。

合同中的旧失败与比较值不覆盖。变更实现或用例定义后，受影响旧结果记为失效；未受影响且证据仍有效的结果继续保留。修复 resolved 只解除暂停，不把用例改为 passed，也不直接进入失败节点之后。

重新核对最早受影响位置的 given；按合法入口进入，必要时执行最短前缀。实际重验、登记结果并同步合同/HTML 后，再继续原路径。新的失败再次进入定位与修复，直到通过或有明确外部阻碍。repair-open/repair-close 及重新提交后均运行 execution_plan.py sync/check，实时 next 必须指向最早受影响访问或待处理修复，不能手动改执行清单推进。

已登记但同步中断时恢复同一提交；修复同步中断时恢复同一修复记录。不得删除失败、活动记录或修复记录来绕过流程。

## 5. 限定保留未受影响的旧驱动结果

修复仅涉及验收入口脚本时，可在改动前将实际执行过的完整原始字节保存到该失败目录的 repair/，并由修复复核记录 resolution.harnessArchive：original 为失败 run.script 的原路径与 SHA-256，archive 为同 SHA-256 的不可变归档，unaffectedCaseIds 为经过逐项差异审查确认未受影响的用例 ID。保留依据必须记录在修复断言报告中；不得仅为减少重验而声明无影响。原 attempt、脚本引用、失败和实际结果不改写。

只有 resolved 的 harness 修复、确有入口脚本变更、归档完整有效、授权早于本次修复且不在影响范围的历史访问，才可使用该脚本归档。归档只替代原入口脚本的历史字节定位，不能替代产品源码、其他依赖、合同、输入或实际结果证据的当前校验。后续未审查的脚本变更、归档变化或新的受影响声明会取消保留。受影响用例必须真实重验；修复关闭仍不表示用例通过。
