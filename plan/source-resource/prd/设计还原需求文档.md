## 1. 唯一需求：UI-001

依据 `plan/source-resource/ui/` 中现有 UI 资料，还原“计划打卡 Android V1”的界面视觉，使各页面的布局、组件、颜色、字体、间距、圆角、渐变、阴影、图标及稿中可见状态与对应设计一致。

本轮只有 UI 设计还原这一项需求。本文的页面清单、视觉规范和验收检查点都是该需求的细化，不构成新增功能需求。

### 1.1 范围

- 覆盖第3节列出的全部23个页面或状态画板。
- 以2份独立组件资料校准主要按钮和三入口导航；方案概览用于整体风格参考，不作为第24个应用页面。
- 还原设计稿可见的页面结构、内容层级、组件外观、文案排版及状态样式。
- 选中／未选、成功／失败／跳过／未记录、只读、警示等状态，按各自页面展示的样例呈现。
- 稿中按钮、筛选、表单等控件的可见样式属于本轮范围；业务操作是否完成、数据如何存储和统计如何计算，不作为视觉还原的前置条件。

### 1.2 边界

**唯一有效的 UI 资料范围为 `plan/source-resource/ui/`。项目根目录下 `resource/` 的历史设计稿、截图、页面映射、设计令牌、设计树快照、历史 PRD 及历史验收产物，均不作为本轮需求或验收依据。**

即使文件同名、画板编号相同或曾被标为已确认，也不得据此从上述历史目录补入参数、页面、默认值、交互流程或功能要求。资料中记载的历史来源路径只说明导出经历，不扩大本轮资料范围。

本轮仅考虑 UI 设计。未提供视觉稿的状态，不自行补成新设计；稿中业务说明按可见文案与排版还原，不因此增加业务规则或功能验收。本轮不要求先完成业务能力再开展 UI 还原。

本文不指定实现技术和代码改造方案，也不判断当前应用页面的完成度、缺陷或工作量。编写本次更新时未读取已有应用实现代码。

使用原则：

1. PNG 用于核对可见外观；同名 HTML 中的普通 CSS、内联样式、SVG 图标及 `data-pencil-name` 用于定位结构和精确参数。CSS 已包含在 HTML 中，无需另找独立样式文件。
2. 需要核对设计节点时，只使用 D1 中的 plan 内设计稿，不回读项目根目录的历史设计稿。
3. 稿中任务名称、日期、数量和备注用于展示视觉场景；还原其排版与状态表达，不要求将样例固化成正式业务数据。
4. HTML 导出用于视觉参考，不要求应用采用 HTML／CSS 技术栈。HTML 引用了 Noto Sans SC 与 Inter 的 Google Fonts；浏览器核对时应确认字体已加载，避免将回退字体的换行差异当作设计要求。
5. 同名 HTML、PNG 与 plan 内设计稿发生冲突时，记录具体文件、节点或画面位置，确认当前采用的版本；不静默拼接不同版本，也不使用历史业务规则裁决。
6. 本文不以历史文档的确认状态、测试状态或实现状态作为 UI 工作的启动条件。

## 4. 统一视觉规范

本节参数从 `plan/source-resource/ui/` 当前 HTML + CSS 中核对，不依赖历史设计令牌或快照。所列为常见样式及代表性实例，局部差异以对应页面为准。

### 4.1 风格与材质

- 冷银灰页面背景、银色金属面板、多段渐变、高光边缘、轻外阴影与局部内阴影。
- 主要按钮保留银色渐变；已选星期控件保留深石墨渐变；浅色选中、结果选中及危险按钮按各自页面区分。
- 卡片、输入框、按钮、标签沿用各自的小圆角样式，保持稿中的直角感。
- 保留主次按钮、结果按钮、危险操作与警示区域的视觉层级。
- 已画出的渐变、高光、边线及阴影不简化为单色平面样式。

- 输入框：#FAFBFC 表面、#AEBBC6 边线与 `inset 0px 1px 3px #2437471A` 内阴影。

### 4.3 字体与布局参数

本表使用当前导出 CSS 的逻辑像素描述设计尺寸。移植到目标平台时保持逻辑比例，不将截图像素或 CSS 盒模型补偿值直接当作页面尺寸。

| 项目 | 当前设计参考 |
| --- | --- |
| 中文文字 | Noto Sans SC，回退为 system-ui、sans-serif；按对应节点字重、行高与换行核对 |
| 系统时间／日历数字等 | Inter，具体按同名 HTML 节点，不统一替换所有文字字体 |
| 常规页面标题 | 常见22px／700、33px行高；图21、22等有23px／35px行高的局部差异 |
| 区块与卡片标题 | 常见16px／700；任务标题等存在17px及其他局部字号 |
| 正文／辅助信息 | 存在15、14、13、12、11px等层级，行高按节点，不能统一设为固定比例 |
| 日历日期／分数 | 12px／10px；分数600字重、#866500 |
| 常规页面左右边距 | 20px；页面内容常见 `padding: 12px 20px 20px`、块间距16px |
| 输入框内边距 | 常见上下14px、左右12px；边框与2px圆角按节点 |
| 主要按钮 | 常见48px高、2px圆角，文字居中；页面内宽度随内容容器核对 |
| 卡片／面板圆角 | 常见3px；标签存在1px，控件存在2px等局部差异 |
| 底部导航 | 三列等宽，单项70px高、图标23px、标签11px、图标与标签间距3px |

图标按 HTML 中的 SVG 轮廓、粗细、尺寸、位置与对齐还原。结果沿用稿中“✓成功、×失败、—跳过、○未记录”等符号、文字和颜色组合。页面状态栏与底部系统区域按整页 PNG 对照，不将组件独立截图的透明边距加到页面布局中。

### 4.4 日历画板重点

仅对齐 [11-日历 HTML](../ui/11-日历.html) 与 [PNG](../ui/11-日历.png) 已有视觉，不追加统计算法或日期业务规则：

- 月份标题、切月箭头、周一起七列、日期格、选中边框与列表区按稿定位。
- 稿中今日为9日：#E0E6EB浅银灰底、加粗日期，不显示点、勾或分数；选中8日使用独立的2px、#263440边框。
- 5日的绿色勾、6日与7日的0/1、8日的2/5、无下标日期及跨月弱色日期，分别对齐画板中的样例，不从样例推导计算规则。
- 日期12px，分数10px／600、#866500；保留字号层级。全部完成勾的示例为11px／700、#006E3A。
- 月历容器左右内边距2px，月份行额外左右14px，列间距2px；星期与日期列居中对齐。
- “10月8日 · 5项计划”标题下的“全部状态（5）”筛选框、彩色结果与明细间距按稿呈现，不增加稿中没有的解释行。

## 6. UI-001 验收标准

以下均为同一需求的视觉检查点，不是独立功能需求。验收关注界面是否与本次 plan 内设计一致，不以业务能力完成作为前置条件。

| 检查点 | 通过条件 |
| --- | --- |
| A01 覆盖完整 | 第3.1节23个页面均有对应视觉对照，画板内已有状态样例不遗漏；第3.2节组件用于一致性核对 |
| A02 布局一致 | 标题、分区、卡片、字段、按钮、导航的顺序、位置、对齐、留白及纵向关系与对应页面一致 |
| A03 视觉参数一致 | 色彩、字号、字体、字重、行高、圆角、间距、渐变、高光和阴影符合当前 HTML 与 PNG；局部差异按对应节点核对 |
| A04 组件一致 | 输入框、选项、标签、按钮、进度、日历和提示面板的样式、尺寸关系、图标及文案层级与稿一致 |
| A05 状态一致 | 稿中已画出的选中／未选、彩色结果、只读、警示等视觉状态分别可对照；不要求业务逻辑先生成这些状态 |
| A06 比例正确 | 以393逻辑像素宽度核对页面，2倍导出图不误用为786逻辑像素页面；长画板不压缩变形，组件阴影边界不作为主体尺寸 |
| A07 日历一致 | 图11日期、分数、勾、今日底色、选中边框、跨月弱色、筛选框与明细列表符合第4.4节 |
| A08 证据明确 | 逐页标注序号、plan 内参考文件、实际截图、参考尺寸、状态及差异复核结果；未核对项明确标识 |
| A09 依据有效 | 需求、参数与验收结论均可追溯到 plan 内 UI 文件；不引用项目根目录 resource 的历史产物补充或替代当前设计 |

### 6.1 视觉对照方式

- 按相同逻辑宽度、字体比例与场景，进行并排或叠加对照。长画板使用完整滚动截图或连续截图，不拉伸压缩。
- 优先核对页面结构和组件定位，再核对文字、颜色、材质、图标及细部间距。
- 动态内容可不同，但排版、层级、尺寸关系和所展示状态应与参考场景对应。
- 设计资料没有给出相似度百分比或像素误差容限，不虚构已确认阈值；依据明确参数及逐页差异复核判断。
- 发现差异时记录对应 HTML／PNG、节点名称与具体位置；资料不一致时按第2节处理，不以历史 PRD 或业务实现状态替代视觉对照结论。
