# 原子需求图规范

## 1. 原子需求与允许进入方式

每条正式状态迁移恰对应一个原子需求：初态—有向迁移—终态。节点以 transitionId 引用原迁移；初终态事实、内嵌 operation、实际条件、输入、结果关系及来源继续由状态图维护。全局约束沿用原规则，不复制为另一套可编辑内容。

迁移的初态 isInitial=true 时，其对应原子需求为起始需求。首次访问须选择起始需求；此后按以下两种方式进入下一个需求：

| 进入方式 | 成立规则 |
| --- | --- |
| 普通衔接 | 上一个需求的终态 ID 等于当前需求的初态 ID |
| 重新进入 | 当前需求为起始需求，允许在任何一次访问之后重新进入 |

相等只比较同一正式状态图中的状态 ID。标题、相似事实、截图或文件名相同不构成普通衔接。重新进入使用已确定的起点进入或准备方式，不在状态图中新增业务动作、条件或虚构状态。

每次进入一个原子需求计一次访问，重复进入也计数。重置准备过程本身不是原子需求节点；重入起始需求的那次访问计一次。要求覆盖全部需求，终点可为任意需求，无需额外返回起始需求。

原状态图中的视觉与功能事实均按同一规则处理。独立静态状态没有迁移时，保留在状态图，不为凑原子需求新增操作；原子需求为空时，覆盖序列为空、最少访问数为 0。

## 2. JSON 契约

使用 [atomic-requirements.schema.json](../assets/atomic-requirements.schema.json)，默认输出 atomic-requirements.json，与状态图放在同一目录。事实、动作或结果变化时，先修改状态图并审查受影响部分，再重新生成派生图。

### 2.1 根字段

| 字段 | 含义与规则 |
| --- | --- |
| schemaVersion | 取 Schema 规定的数据结构标识 |
| title | 状态图标题后追加“ · 原子需求图” |
| revision | 与来源状态图相同 |
| stateGraph | 正式状态图的相对路径 path 及规范化 JSON 的 sha256 |
| requirements | 全部原子需求节点，与正式迁移一一对应 |
| edges | 仅包含所选最优覆盖序列实际使用的有向边 |
| coverage | 访问顺序、访问数量与精确最优性结果 |

最终文件不保存摘录、澄清、范围映射或语义审查过程。stateGraph 引用正式状态图，状态的 source 仍直接引用原文档或 UI。

### 2.2 原子需求节点

| 字段 | 含义与规则 |
| --- | --- |
| id | R- 加 transitionId，例如 R-T001 |
| transitionId | 正式状态图中唯一迁移的 ID |

通过该引用读取完整三元组、实际分支及效果；通过迁移的 from、to 读取状态事实、观察方法、UI 结构和原截图。不单独设计 operation ID。需求节点按迁移 ID 的 Unicode 字符顺序排列；同一操作的不同结果迁移分别对应原子需求。

### 2.3 路线边

| 字段 | 含义与规则 |
| --- | --- |
| id | 按访问序列中相邻节点对首次出现的顺序，使用 L000001 等连续编号 |
| from | 上一次访问的原子需求 ID |
| to | 下一次访问的原子需求 ID |
| kind | handoff 表示普通衔接；restart 表示重新进入起始需求 |
| viaStateId | 仅 handoff 必填，记录共同的终初态 ID；restart 省略 |

相邻需求满足普通衔接时统一记为 handoff；否则只能在目标为起始需求时记为 restart。边不定义新的 operation、condition 或全局约束。

从 coverage.sequence 的相邻访问对建立边，同一有序节点对只保存一次；循环或重复边只有实际被所选路线使用时才保留。候选后继关系只用于求解，不输出完整候选边集，也不保留未使用的捷径或分支。

图中的每个需求仍只画一个节点。访问序列记录重复次数与先后顺序，图中的边是该序列的去重投影；重放完整顺序时以 sequence 为准。

### 2.4 最优覆盖结果

| 字段 | 含义与规则 |
| --- | --- |
| algorithm | min-cost-circulation-with-free-restarts |
| optimality | 精确求解并通过检查后为 proven |
| sequence | 原子需求 ID 的完整有序访问序列，保留重复访问 |
| visitCount | sequence 长度，首个节点和所有重复进入均计入 |
| minimumVisitCount | 精确算法得到的全局最小访问次数，应与 visitCount 相等 |
| additionalVisitCount | visitCount 减去原子需求节点数 |

未完成求解、路线不合法或检查失败时不输出带 proven 的完成产物，不以启发式结果代替精确最优值。

## 3. 精确最少访问算法

### 3.1 求解模型

一迁移一需求使问题等价于：覆盖原状态图的全部有向边，每条边的经过次数计入需求访问次数，并允许随时重置到任一正式起点。

以正式状态为顶点建立内部流网络，加入仅用于计算的超级顶点 O：

1. 每条原迁移边设置流量下界 1，单位费用 1，表示该原子需求至少访问一次。
2. 从每个状态到 O 建立费用为 0 的重置连接。
3. 从 O 到每个正式起点建立费用为 0 的进入连接。
4. 要求所有顶点流入等于流出，求整数最小费用循环流。

超级顶点和虚拟连接只存在于算法内存中，不成为业务状态、原子需求或额外产物。最终原子图仅用 restart 说明实际所选的重入连接。

### 3.2 求解与恢复顺序

先给原迁移各分配一次经过，计算各状态的流量缺口。使用残量网络上的逐次最短增广路补齐缺口：原迁移的额外经过费用为 1，重置及进入连接费用为 0。最短路使用 Bellman–Ford，允许残量反向边具有负费用；完成后检查残量网络不存在负费用环，并核对流费用与势函数给出的对偶下界相等；二者不符时求解失败。

当原图包含多个相互独立但有合法起点的分量时，给每个起点加入 O→起点→O 的零费用平衡连接，使所需边统一连入可遍历网络。随后使用 Hierholzer 算法恢复从 O 开始的欧拉经过顺序，删除虚拟连接，仅保留每条原迁移对应的需求 ID。

确定性要求：状态和迁移按 ID 排序，最短路仅在距离严格变小时更新前驱；恢复经过时采用固定顺序，原迁移优先，进入连接其次，重置连接最后。多个同费用方案按此固定规则选择一条，不额外优化重入次数或显示边数量。

### 3.3 最优性依据

任一合法覆盖序列都能展开为上述网络中的循环流：普通衔接沿原迁移连续经过，重入和最后结束通过零费用虚拟连接补齐。其费用恰等于总需求访问次数，因此最小费用是任何合法方案的下界。

整数最小费用流可经零费用连接恢复为一条合法覆盖序列，所有原迁移至少经过一次，恢复后的访问次数等于该费用。故这个下界可达到，得到的是全局最小访问次数，而非局部贪心或近似结果。终点通过免费虚拟连接结束，不强制多访问一个需求来返回起点。

### 3.4 裁剪输出与验证边界

计算完整最优访问序列后，仅保留该序列的相邻访问对，其他候选有向边删除。重新进入边的目标必须是起始需求；其他边必须满足前项终态等于后项初态。

本算法优化的是已建模状态和允许重入规则下的需求访问数量。执行实例继续使用状态图中的事实、输入、分支样例及全局约束；若相同状态背后仍存在影响后继的不同前提，返回状态建模步骤澄清或拆分，不能由路线算法添加隐含条件。

## 4. HTML 表达与到达路径

复用 [HTML 设计规范](html-design-spec.md)及 [graph.template.html](../assets/graph.template.html)。拖拽、选中边置顶、侧栏开关、键盘操作、默认列布局及坐标和缩放保留按共用规则执行。

| 项目 | 原子需求图规则 |
| --- | --- |
| 节点 | 一个原子需求，显示 ID、动作、实际分支摘要及初态→终态 |
| 起点 | 对应迁移的初态 isInitial=true |
| 实线 | 所选路线中的普通衔接边，连接共同状态 |
| 虚线 | 所选路线中的重新进入起始需求连接，文字明确标注重入 |
| 计数 | 分别展示唯一需求数与包含重复的最少访问次数 |
| 默认列 | 按所保留路线边计算距任一起始需求的最少边数 |

### 4.1 点击需求显示到达路径

点击需求时，默认选择它在最优序列中的首次到达位置。向前找到距该位置最近的一次起始需求访问，以它为本段起点，展示到当前到达位置的连续子序列；当前需求本身为起始需求时，该路径只包含当前这次访问。

图中仅显示这条到达路径涉及的需求和实际相邻边，不显示候选捷径或普通邻居；侧栏用有序路径列表显示先后顺序和总覆盖序列中的步骤编号。重复需求在图中保持一个节点，侧栏列表保留所有重复步骤。

一个需求在最优序列中出现多次时，侧栏提供“到达次数”选择，列出对应的总序列步骤。切换时展示该次到达所属段的路径。再次点击当前聚焦需求恢复全图，选中内容保留。

路径切换、恢复全图和到达次数切换只改变可见性与详情，不重排节点、曲线、标签，不自动缩放或平移；手动拖拽结果保留。顶部聚焦选择器和键盘入口遵循相同的路径规则。

### 4.2 详情内容

需求详情展示到达路径及 GIVEN 初态—WHEN 动作（实际条件）—THEN 终态，按需展示动作输入和结果关系。初终态继续显示事实、观察方法、UI 结构、原截图及状态自身的直接来源。侧栏不显示“迁移直接来源”章节。

普通路线边详情说明共同状态及其事实；重入边详情说明目标起始需求和进入状态，不虚构共享终初态。全局约束从同版状态图读取，在概览中集中展示。

页面内嵌原子图和绑定的正式状态图快照，两份模型均参与同步检查。位置、缩放、选中及到达次数是临时视图数据，不写入图 JSON。

## 5. 生成、门禁与收尾

~~~text
python <skill-dir>/scripts/atomic.py build <output-dir>/state-transitions.json --workspace <project-root>
python <skill-dir>/scripts/atomic.py check <output-dir>/atomic-requirements.json --workspace <project-root>
~~~

build 先检查正式状态图，再精确求解并生成 JSON/HTML。check 为只读检查，结果输出到终端，不另留报告或过程面板。

| 门禁 | 通过标准 |
| --- | --- |
| Schema与来源 | 字段符合 Schema，引用在工作区内，正式状态图及来源检查通过，摘要与修订一致 |
| 一一映射 | 全部正式迁移恰对应一个需求，无遗漏、重复或失效引用 |
| 合法进入与覆盖 | 首次为起始需求，每次进入符合普通衔接或起点重入，全部需求至少访问一次，无未知 ID |
| 精确最优 | 重算最小费用结果，访问次数达到下界，序列及固定选择规则一致，重复访问统计正确 |
| 路线边裁剪 | 边集与所选序列的相邻访问对去重结果完全一致，kind及共享状态正确，无多余候选边 |
| HTML同步 | 原子模型、状态快照及共用模板与当前文件一致 |
| 路径交互 | 首次到达、重复到达切换及恢复全图正确，路线列表和可见边一致，坐标与缩放不变，侧栏无迁移直接来源 |

算法自测使用[独立穷举搜索](../scripts/test_coverage_route.py)核对小图的全局最优值，覆盖分支、死路、开放终点、多起点、独立平衡分量、自环与平行迁移；共用 Canvas 模拟验证两类页面交互。模拟结果与实际浏览器验收分别报告。

完成状态图的分析、澄清及语义审查后，work.py finalize 一并检查状态 JSON/HTML、原子 JSON/HTML 和工作记录；任一失败保留工作记录，全部通过后按主 Skill 清理过程资料。仅更新已有模型的算法派生产物时，先核对来源是否变化，沿用仍有效的分析；事实、动作或结果变化时重新审查受影响部分。
