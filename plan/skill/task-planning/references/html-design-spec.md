# Test Case图HTML规范

使用[test-cases.template.html](../assets/test-cases.template.html)生成只读验收图。图表沿用需求分析图的布局和交互规则；侧栏用于按步骤阅读与验收，不承担来源审计和代码映射展示。

## 1. 图表与到达路径

- 默认显示全部用例及所选最少访问路线边。从主起始用例和具有独立准备方法的补充用例出发，以最短边数BFS分列；起点第一列，同列稳定排序。
- 点击用例显示最优序列中最近一次起点至本次访问的完整路径，默认首次到达；重复用例可切换“到达次数”。再次点击当前用例恢复全图。
- 到达路径按实际访问顺序显示可读动作及到达场景。步骤号用于定位次序，不以变量名、状态ID或需求映射表代替场景名称。
- 聚焦仅隐藏无关元素，保留节点、曲线、标签、平移和缩放，不自动重排。
- 节点和连线可拖动，连线保持端点关系；选中边置顶且优先命中。重入边用虚线标注。
- 侧栏边缘始终保留收起/展开入口；内容更新不改变显隐。窗口或侧栏尺寸变化只调整画布尺寸。
- 无底部选择列表；保留工具栏、方向键、Shift+方向键、Enter和Esc操作。

## 2. 侧栏阅读结构

节点详情围绕以下六项组织。用例标题使用可读场景和动作，技术字段只用于后台解析。

| 内容 | 展示要求 |
| --- | --- |
| 到达路径 | 当前所选次序从本段起点到此用例的完整步骤，可切换重复到达 |
| 前置条件 | 上一个用例应已到达的场景及共同成立的事实；明确能否继续本步 |
| 当前操作 | 执行者、本步动作和实际存在的结果分支；必要输入用可读含义说明 |
| 预期结果 | 执行后应到达的场景和可判定结果，保留所需视觉/功能事实及结果关系；存在对应UI图时同时展示 |
| 验收方式与证据 | 分别显示视觉、功能是否适用；适用时逐项显示通过标准、测试类型、环境及明确证据形式 |
| 当前验收状态 | 读取本例执行记录；没有实际执行证据时显示未执行，列出影响执行的待准备事项 |

前置条件按所选访问位置解析，不只展示一段通用准备文字：

1. 本次是普通衔接时，显示上一项的可读动作、它应已到达的终态场景和事实，并核对其等于本步初态。
2. 本次是首次起点或重入时，显示本步应进入的起点和准备方法，不把上一项无关终态写成前置条件。
3. 独立规则/回归用例显示其隔离准备和可观察前提，不伪造业务状态或前序共享状态。
4. 切换到达次数时，同时更新路径、前置位置和上一项说明，不改变图坐标与视口。

预期结果用终态的自然语言事实和expected.conclusion表达，不输出断言JSON。结果关系需要补充时显示其事实陈述。侧栏可以展开这些可读细节，但不折叠藏入技术变量表。

### 2.1 预期结果的UI图

- 从本例expected.stateId对应的正式终态读取UI来源及其截图；不得用初态图片替代终态图片。
- 终态存在对应UI图时，在预期结果文字之后展示，标题为“预期 UI 图”，图注明确“预期 UI 参考图”。同一图片只显示一次，多个对应画面按来源顺序展示。
- 图片保持原始比例并适应侧栏宽度，可点击查看完整尺寸；图片路径相对绑定状态图解析，不显示路径、节点ID、哈希或来源清单。
- 图中的名称、日期等示例数据不要求与本次值相同；实际预期仍由UI结构、适用规则及本次输入确定。参考图不能冒充实际取证截图或通过结论。
- 没有直接对应终态UI图时省略图片区，不使用空白占位或任意画面补齐。独立全局/回归用例没有单一目标画面时保留可读结果。

## 3. 视觉、功能验收与状态

字段含义及选择规则遵循[验收分类与证据规范](test-cases.md#21-视觉与功能验收)。页面分别标注“视觉验收”“功能验收”；不适用的一类显示“不适用”及简短原因。

适用检查使用可读卡片：通过标准、脚本验收/浏览器验收、运行环境、所需证据及取证内容。内部script、browser、runtime、native等枚举映射为中文，不直接展示。原生应用检查显示为“脚本验收 · 原生应用宿主”；浏览器页面检查显示为“浏览器验收 · 浏览器”。

证据形式明确显示为界面截图、DOM结构、原生节点树、组件树、布局测量、检查结果、状态快照、调用记录或测试输入；每种形式附所需内容。规划阶段注明“待采集”，预期参考图单独放在预期结果区，不能充当执行证据。截图无法证明持久化等功能效果时，按功能检查要求补充数据、调用或查询证据。

状态从execution读取并显示中文。计划文件的not_run显示“未执行”；图形被选中、规划门禁通过、所需证据清单存在，都不能将它改成通过。执行前置项仅展示可读说明，不输出前置项ID或批量用例映射。

## 4. 信息取舍与可读性

- 侧栏不展示直接来源、文档路径、哈希、条款摘录、原始JSON、节点ID清单、参数映射、变量名、完整数据契约、Mock载荷和任务映射表；这些内容继续保存在正式JSON及任务计划中。
- 必要的测试数据和响应准备通过可读动作、分支说明及取证要求表达，不将控制器变量或内部协议直接交给阅读者理解。
- 不堆叠初态/终态的整段来源资料，不重复相同事实。短标题、分段说明和证据清单应支持逐项阅读。
- 路线边详情用可读前后用例名称及共享场景说明普通衔接；重入时说明重新准备的入口。边详情同样不显示来源或映射表。
- 全局概览展示全局验收主题、未执行状态和待准备事项；完整约束、来源及覆盖映射仍保留在绑定模型中。

## 5. 同步与门禁

页头保留唯一用例数、主/补充用例数、最少总访问和重复次数。环境矩阵和多层检查不计为额外图节点。

安全嵌入原始用例模型、绑定状态图、原子图及任务计划快照，并检查摘要；侧栏不展示审计字段不影响正式数据完整性。页面操作只改变内存视图，不修改模型或验收状态。

生成器检查HTML与最新模板及快照同步。Canvas模拟测试须检查六项侧栏内容、实际前序场景、重复到达切换、视觉/功能适用性、测试与证据中文标签、仅使用两类验收名称、终态UI参考图的正确关联与路径、无来源及技术映射泄露，并保留拖拽、置顶、收起/展开、聚焦位置和模型不变的检查。真实浏览器渲染单独验证，不能以模拟测试宣称实际视觉验收通过。

## 7. 执行结果展示

侧栏从 execution 显示中文的通过、未通过、部分完成、暂不能执行及证据已失效状态；按视觉/功能、检查与路线访问展示实际观察及证据链接。链接相对本 HTML，描述使用证据的可读名称，不堆叠变量或源文件映射。概览统计真实状态，不将所有状态固定写成未执行。预期 UI 参考图持续显示，和实际截图区分。JSON、任务 Markdown 与 HTML 由同一执行记录同步生成；不单独修改 HTML 的状态文本。
