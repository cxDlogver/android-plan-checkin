# 开发验收入口

设置 `APP_VARIANT=development` 后运行 Metro，并安装 `com.xiang.plancheckin.dev`。通过深链接 `plancheckin-dev:///native` 进入技术页；入口不出现在产品导航。读回真实 SQLite 参数、版本、库路径、当前事实与单一查询快照。

测试控制还会核对真实原生 applicationId，只允许 `.dev` 身份清空夹具库。时钟、种子生成器和故障实现通过 Metro 别名选择，仅随开发构建进入bundle；正式构建使用系统时钟和空钩子，`/native` 返回业务首页。正式bundle的实际资源及开发标记排除结果见 [bundle-audit.json](bundle-audit.json)。

测试时钟在内存中冻结，ISO输入必须包含Z或明确时差。包内命令信封和应用服务使用同一时钟；修改时间后刷新快照，既有表单继续按跨日重新确认规则处理。重启进程恢复系统时钟，夹具数据继续保存。

| 夹具 | 合法数据与操作 |
| --- | --- |
| F01 | 固定、每周、一次性与不要做；执行核心结果/备注闭环 |
| F02 | 暂停前记录、暂停区间及已恢复当前阶段；测试旧阶段/暂停空日禁止补记 |
| F03 | 过去8个要求日6成功2失败；今日未记录用于6/8、7/9与6/9 |
| F04 | 三周历史，完整执行周/整周暂停/恢复；当前周不入历史分母 |
| F05 | 昨日100个要求，99成功1未记录；精确99/100，今天隐藏标记 |
| F06 | 清洁核心计划；结合一次性COMMIT前失败/成功后丢失返回控制 |
| F07 | 80字名称、1000字说明、2000字备注；字号/滚动/草稿返回 |
| F08 | 清洁核心计划；选择纽约时区及2026-03-08/11-01明确时差瞬间，测试DST/跨日 |
| PERF | 40固定、40周目标、20一次性；三年窗口、10000条周期记录及10条一次性结果；用于原生分页/统计预算 |

故障只执行一次。COMMIT前失败应整体回滚；“保存成功后丢失返回”会保留已提交事实和receipt，原页面保留同信封重试后按receipt返回成功，不重复新增。可手动取消故障。

夹具生成器版本2使用确定种子。同版本、业务日期、固定时区和名称会生成相同ID与事实内容；版本/seed/日期/行数/事实及数据库SHA-256见 [fixture-manifest.json](fixture-manifest.json)。本次仅回归受影响的夹具集成用例，真实9表约束、40/40/20比例、三年首末日期及可复现性均通过。

API36原生SQLite/Hermes参数与核心创建、取消、提交、修正和导航流程已独立留证，见[实时进度](开发进度.md)。API29、完整BDD与八组合继续分别记录；宿主结果不代替原生验收。
