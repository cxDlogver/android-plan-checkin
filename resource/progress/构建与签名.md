# 构建与签名

正式身份：`com.xiang.plancheckin`；开发身份：`com.xiang.plancheckin.dev`。

正式构建先在新终端清除 `APP_VARIANT`，执行 `pnpm exec expo prebuild --platform android --no-install`。开发构建设置 `APP_VARIANT=development`，执行相同 prebuild，再运行 `pnpm start` 与 Android debug。两者不可并行修改同一生成目录。

Release 签名插件要求以下环境变量，仅在当前构建进程中传入：

- `PLANCHECKIN_KEYSTORE`：仓库目录以外的长期密钥文件。
- `PLANCHECKIN_STORE_PASSWORD`：密钥库密码。
- `PLANCHECKIN_KEY_ALIAS`：签名别名。
- `PLANCHECKIN_KEY_PASSWORD`：密钥密码。

插件拒绝缺少签名参数、仓库内部密钥、以及不存在的密钥文件。正式 release 绑定 `signingConfigs.release`，不会回退到 Expo 模板的 debug 密钥。密码不得出现在命令参数、Git、证据日志或截图中。密钥及密码由所有者单独保存，后续覆盖升级必须复用同一签名。

`node scripts/native-build.cjs debug` 默认仅构建 x86_64 模拟器开发包；release 默认构建 arm64-v8a/x86_64，可通过 `PLANCHECKIN_ARCHITECTURES` 缩小测试构建 ABI。未配置正式签名或生成目录身份错误时，release runner 会提前拒绝。

当前真实状态以 [开发进度](开发进度.md) 中原生构建记录为准。独立 release、签名摘要、覆盖升级和完全离线运行在实际生成及执行前均保持 NOT_RUN。

2026-10-10 用户确认生成新的长期签名密钥。密钥与 DPAPI CurrentUser 加密密码配置保存在 `C:\Users\xiang\.android-plan-checkin-signing`，目录继承权限已关闭，仅当前 Windows 用户可访问。访问权限和公开证书摘要见 [release-signing.json](release-signing.json)。私钥不进入 Git 或 APK 交付目录。

使用 `scripts/Release-PlanCheckin.ps1 -Action Prebuild` 生成正式配置，再执行 `-Action Build`。后续覆盖升级给两个步骤传入同一组 `-VersionCode 2 -VersionName 1.0.1`，每次递增 versionCode。脚本只在构建子进程中解密和传入密码；构建结束即清除临时环境变量。

只修改 JS 界面时，可给 Build 传入 `-ReuseNativeFrom <已成功release的result.json>`。该模式要求生成的原生配置、插件、依赖锁完全一致，并逐一核对缓存 `.so` 与此前签名 APK 内库的 SHA256；任一缺失或变化立即拒绝。通过后跳过这些库的 CMake 构建，仍重新生成 Hermes、资源和签名 APK。版本、依赖或原生配置变化必须使用完整构建。本机第二次增量构建遇到 Ninja 260字符路径限制，本次导航修复使用上述受控方式，校验清单保存在对应构建目录 `native-reuse.json`。

最终交付来源见 [build-manifest.json](build-manifest.json)：包含 APK/证书/内嵌代码/静态字体摘要，并将实际源映射与构建启动前冻结的项目源码逐一比较。文件被 prebuild 清理后，不允许用重新生成的 APK 冒充旧证据；开发包曾从隔离 AVD 读回并确认原始摘要，恢复回执单独保存。

请对上述签名目录做安全备份。DPAPI 配置绑定当前 Windows 账户，换机前需要单独的加密密码备份和恢复演练，避免长期证书无法继续用于覆盖升级。
