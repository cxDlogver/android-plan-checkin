# 验证去重与消耗控制

当前继续完成原 BDD 基线。减少执行和输出，不降低原验收要求。

1. 使用 `run-bdd-uncompleted.cjs` 或显式缺口入口。已闭合 PASS 与有效 SHA 的业务操作直接复用；不因验收脚本或汇总文案变更重跑业务。
2. 失败续验只执行未通过的后缀。保存/归档/重启已经成功时，恢复有来源的已接受事实，补读回、视图或剩余交互；原失败报告保留。
3. 父条款未闭合不等于功能未验证。优先核对现有断言、完整 DTO、SQLite、截图及操作日志，补来源或汇总，避免重复 When。
4. 缺少前画面时，只恢复明确标识的原始 Given 或派生状态拍摄。不得再次保存、归档或提交来制造前后截图。
5. 日常状态使用 `scripts/bdd-economy-status.cjs`，输出父条款计数、缺失核心实例和活动项；不扫描历史运行目录、不做全量摘要检查、不读取大批日志。
6. `update-bdd-coverage.cjs` 只在阶段结束或最终交付时执行。最终完整 SHA 校验保留；日常状态不能作为完整性验收结论。
7. 批次启动时一次核对需要复用的闭合报告。只核对本次直接依赖；不递归检查无关失败祖先，不将失败产物改成 PASS。
8. 当前变化为验收脚本与证据元数据。产品代码与正式 APK 未变时，不重建 APK，不重跑已通过的类型、领域、数据库和迁移测试。
9. 八组合仅覆盖基线规定的核心用例与显示专项；其他功能保留两 API 基础组合。实测 TalkBack、正式 APK 性能/升级/备份不能以源码或树结构代替。
10. 不并发操作同一设备；批次之间复用模拟器、Metro、Appium 和桥接服务，减少启动、恢复和覆盖界面造成的失败。

检查结果：现有矩阵与续验入口会校验 PASS 证据后跳过已通过业务。发现的可减少开销是频繁全量证据扫描、长日志输出、父条款未汇总时误认为需要再执行，以及不带筛选直接调用完整 UI 模块。

执行时区：Asia/Shanghai。2026-10-12 更新。
