# 命令与查询契约

> 技术基线0.8，T15已整体确认；接口是后续实现的明确约定，当前尚未编写应用代码。依据[主技术文档](../技术设计文档-计划打卡-Android-v1.md)、[数据契约](数据结构与迁移契约.md)。

## 1. 公共命令信封

所有11个命令统一携带以下结构，业务表仅列特有字段：

```typescript
type CommandEnvelope<K, P> = {
  commandId: UUID;
  kind: K;
  issuedAtMs: UtcMillis;
  payload: P;
};
type ExpectedPlan = { planId: UUID; expectedPlanRevision: number };
type FirstRecordConfirmation = {
  confirmedToday: BusinessDate;
  confirmedEntryKind: 'ordinary' | 'backfill';
};
type RuleConfirmation = {
  field: 'weekday_mask' | 'weekly_target';
  confirmedEffectiveOn: BusinessDate;
};
```

UUID和issuedAt在用户最终确认时生成并冻结；提交中禁用按钮。相同内容的重试复用信封，重新编辑/确认生成新ID，不能把旧ID绑定新内容。应用服务用expo-crypto计算SHA-256，不信任调用方提供的摘要；摘要覆盖kind、issuedAt、完整payload（含ID、revision、确认日期），按键排序的确定性JSON编码；文本先执行领域归一化，undefined不入结构，枚举/数字/日期保持类型。receipt只保存64位十六进制摘要，不保存JSON或用户文本。

## 2. 每个命令的特有契约

| 命令 | payload | 最新事实校验与提交内容 |
| --- | --- | --- |
| CreatePlan | planId、name、description、type、direction、startsOn及该类型初始规则 | planId在首次确认固定；有效日期/码点校验；plans和规则一起插入；对象存在时只允许对应receipt重试，不能按同名认定重复 |
| SubmitCycleRecord | ExpectedPlan、recordId、businessOn、result、note、FirstRecordConfirmation | 类型fixed/weekly、目标日资格、当前阶段、普通/补记提示一致；同日已有记录返回冲突；不转为修改 |
| ModifyCycleRecord | ExpectedPlan、recordId、expectedRecordRevision、result、note | 记录属于目标计划；ordinary、businessOn=today且未归档；不接收新业务日/entryKind；首次实际修正保存原值 |
| SubmitOneTimeResult | ExpectedPlan、resultId、outcome、actualCompletedOn（仅完成）、note、FirstRecordConfirmation | 尚无结果；完成日范围；失败/取消仅today；固定业务日和截止引用；补报同时立即归档 |
| ModifyOneTimeResult | ExpectedPlan、resultId、expectedRecordRevision、outcome、note | 普通当日未归档；completed时actualCompletedOn强制原businessOn，否则null；业务日/截止引用不变 |
| EditPlan | ExpectedPlan、changes、ruleConfirmations | 运行中白名单；changes只包含真实变动字段；类型/方向/开始/时区不可改；终态一次性不改截止；T7/T12规则替代/取消；确认边界不能漂移 |
| RequestPause | ExpectedPlan、eventId、confirmedEffectiveOn | 循环运行中，无有效待生效状态申请；confirmedEffectiveOn必须为最新today+1；事件从该业务午夜生效 |
| RequestResume | ExpectedPlan、eventId、confirmedEffectiveOn | 循环已暂停，无有效待生效状态申请；最新today+1；恢复创建新阶段，不解锁旧阶段空日 |
| CancelPendingState | ExpectedPlan、eventId | 目标事件属于计划且effectiveAt>now；只标取消；已生效拒绝；不恢复已关闭阶段 |
| ArchivePlan | ExpectedPlan、eventId | 立即归档，循环或未归档一次性适用；保存真实now和today；取消未来申请；已有记录保留只读 |
| PermanentlyDeletePlan | ExpectedPlan | 已归档、二次确认的同一revision；级联历史与短期防重放标记同事务；已删除重复命令返回TARGET_REMOVED |

所有ID关联、枚举和业务日期重验。CAS更新用`WHERE id=? AND revision=?`，影响行数必须1；记录修正同时检查计划与记录revision。每次命令只增一次该计划revision。无实际变化返回成功，不制造原值、修改时间或新业务revision，仍可保存幂等receipt。

CreatePlan跨日时按保存当日重新校验“开始/截止不能早于今天”；不自动挪动已选日期。管理确认包含具体生效日期：暂停/恢复、星期和N若跨日使生效边界改变，返回CONFIRMATION_STALE并刷新确认内容，不静默把10/10改为10/11。仅即时名称/说明编辑不增加无意义的跨日阻断。

本轮P1创建默认值已确认：固定星期表单初始为空选择，未选不得发出有效CreatePlan；用户手动选择后序列化weekdayMask为1–127。应用服务仍拒绝0、空值及超范围，不能自动全选。编辑初值加载现有/待生效规则，不应用新建空默认值；数据表非空有效mask约束保持不变。

## 3. 串行执行与事务顺序

一次队列任务不得调用再次排队的公共方法。内部tx上下文仅在该回调有效；领域函数无SQL，事务内不await用户交互/网络。所有查询、验证入口、生命周期对账都走同一执行器；不提供raw connection、第二SQLiteProvider或独立后台数据库连接。

```text
校验信封结构并预计算摘要
→ 入队，检查receipt（TARGET_REMOVED优先）
→ 捕获一个now/today快照
→ reconcile(now)独立事务：提交合法到期状态；如有变更发布其revision
→ 用户命令事务：读取最新事实，校验权限/revision/确认
→ 写业务行＋原值/事件＋receipt＋data_revision，提交
→ 发布用户事务revision，返回成功
```

对账和用户命令是同一队列任务中的两个顺序事务，中间没有其他业务任务插队。拒绝跨日首次提交只阻止本次用户记录；已依法到期的自动归档可以在前一步落库。对账失败则不执行用户命令；用户事务失败不撤销已提交的对账。存储错误不得以成功receipt掩盖。应用被杀死后不恢复未提交草稿或自动重提交，启动先重查已提交事实；只有原调用会话仍持有冻结信封时才按原commandId查询/重试，不能承诺重启后找回内存中的命令ID。

首次记录必须比较confirmedToday和当前today，再验证confirmedEntryKind与最新资格。DAY_CHANGED保留输入，合法历史日期重新进入补记确认，用户接受只读/归档后生成新信封；若变成暂停/归档/旧阶段，则拒绝且说明。修改记录跨日直接只读，不转补记。一次性失败/取消重新确认当前日，不补报昨日结果。

### 3.1 凭据和重放

重试窗口为issuedAt起7×24小时，非业务日7天。有效窗口内OK receipt摘要一致即返回已提交对象ID和成功状态，允许跨日返回原成功；界面对象内容由最新查询加载，不把新内容声称为原提交快照。摘要不一致拒绝COMMAND_ID_REUSED。TARGET_REMOVED不再核对已清空摘要，直接返回目标已删除。

已过期命令返回COMMAND_EXPIRED，不重新执行；没有receipt也必须检查issuedAt窗口，避免已清理的创建请求复活删除对象。设备时钟异常导致issuedAt晚于now时返回CLOCK_CHANGED并要求重新确认，不声称防篡改。启动/空闲时每批清理最多200个到期receipt；清理不改变用户历史。receipt与业务唯一约束互相补充，不能承诺永久无限重放。

## 4. 返回与错误协议

```typescript
type CommandResult =
  | { ok: true; code: 'OK'; objectId?: UUID; dataRevision: number; replayed: boolean }
  | { ok: false; code: ErrorCode; fieldErrors?: Record<string, string>;
      currentPlanRevision?: number; currentRecordRevision?: number };
```

| ErrorCode | 界面处理 | 是否可复用同一信封 |
| --- | --- | --- |
| VALIDATION_FAILED | 字段错误；保留草稿 | 修改输入后新命令 |
| DAY_CHANGED | 图23，显示新今天、保留输入、显式重确认 | 否 |
| CONFIRMATION_STALE | 最新具体生效日/状态确认 | 否 |
| PLAN_CHANGED / RECORD_CHANGED / RECORD_EXISTS | 加载当前事实，说明变化；不覆盖草稿里的新输入 | 重确认后新命令 |
| DATE_INELIGIBLE / OLD_STAGE / PAUSED / ARCHIVED / READ_ONLY | 显示日期或状态理由，禁用相应保存 | 否 |
| TARGET_REMOVED | 目标不可用，返回来源并刷新数量 | 不执行 |
| COMMAND_ID_REUSED / COMMAND_EXPIRED / CLOCK_CHANGED | 重确认当前事实；不能自动发新命令 | 否 |
| STORAGE_FULL / STORAGE_BUSY / STORAGE_IO | 保留输入，明确尚未确认保存，允许重试 | 内容不变可重试，先查receipt |
| INIT_FAILED / MIGRATION_FAILED / SCHEMA_TOO_NEW | 阻断业务页；重试或安装兼容版本 | 不执行用户命令 |

映射SQLite错误到稳定错误码；不展示SQL、参数或堆栈。失败日志仅错误码、操作类型、schema版本和技术耗时，不含名称/说明/备注/完整payload。STORAGE_BUSY在单连接架构下视为需要调查的异常，不通过无限重试掩盖额外连接。

## 5. 查询快照、缓存与分页

查询作为一个队列任务，读取事实和dataRevision后生成不可变DTO；内部多条SELECT处于同一读事务，不与写命令交错。DTO包含`asOfMs/today/zone/dataRevision`，整个视图共用该快照，不能同屏混用午夜前后分母。查询前进行到期对账；业务午夜、返回前台、成功写入均使相关投影失效。

| Query | 输入 | 返回 |
| --- | --- | --- |
| TodayQuery | 当前快照 | PRD四分区、稳定排序、允许动作；会话仅保存卡片位置，不保存事实 |
| CalendarMonthQuery | month、selectedDate | 42格可见区一次范围读取；days的C/T/marker；选日完整items及额外weeklyBackfills |
| PlansQuery | status、cursor、pageSize | items、nextCursor；状态由事件派生；pageSize默认50，上限100 |
| PlanDetailQuery | planId、展示月份 | 状态/规则/待生效值、统计区间、分子分母、当前连续、月历、权限 |
| RecordQuery | planId、recordId | 结果/备注、原提交/最近修改/原值、补记/已修正、只读理由 |
| SettingsQuery | 无 | 固定时区、真实原生版本或不可用、本机数据边界 |

列表按PRD规定的分区与字段排序，最后加稳定id；分页游标保存对应排序元组，不能只按名称分页。历史记录按businessOn倒序、id补充顺序；游标带dataRevision，期间有变化时重置分页，避免漏项。长列表虚拟化；42格不是42次SQL。缓存键含query参数＋today＋zone＋revision；首版缓存最多保留当前及相邻月3个月，详情按最近10个计划淘汰，可随性能证据优化而不改变规则。

全局状态筛选在完整选日集合上派生；切日重置all，记录返回同日恢复月份/日期/filter/滚动。永久删除后丢弃该目标DTO，来源重新查询；目标失效不能返回旧缓存或提交旧对象。

## 6. 页面路由和自动化接口

提议路由为`/(tabs)/today`、`/(tabs)/calendar`、`/(tabs)/plans`、`/plans/new`、`/plans/[planId]`、`/plans/[planId]/edit`、`/records/new`、`/records/[recordId]`、`/settings`。只传ID/业务日/预选结果/来源会话键；记录页重查资格，不能把路由参数当权限证明。图23为表单错误态，复用同一草稿会话；确认sheet不是独立数据对象。23张设计图是页面与状态集合，不能机械生成23条路由。

稳定testID至少包括`tab.today/calendar/plans`、`plan.create`、`plan.name`、`plan.save`、`record.result.success/failure/skip`、`record.note`、`record.save`、`calendar.month.previous/next`、`calendar.date.YYYY-MM-DD`、`calendar.status.filter`、`plan.pause/resume/archive/delete`、`confirmation.confirm/cancel`、`error.retry`。动态卡片以planId区分，不以名称定位同名计划。testID不得替代TalkBack的自然中文标签；Appium可定位性在两API原生包验证，优先语义/资源ID，不靠固定坐标验收。
