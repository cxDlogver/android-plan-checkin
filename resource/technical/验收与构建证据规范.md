# 验收与构建证据规范

> 技术基线0.8，T15已整体确认；本文件定义后续执行出口，不能作为应用已通过验收的证明。已实测的是模拟器/Appium控制环境，详见[环境记录](../安卓AI验收环境配置记录-20261009.md)。

具体执行拆分为[实施计划 checklist](../实施计划-checklist-计划打卡-Android-v1.md)与[BDD验收 checklist](../BDD验收-checklist-计划打卡-Android-v1.md)（1.0评审稿），通过IP/AC相互关联。本文保留技术门槛及预算；详细Given/When/Then、参数行、断言编号和证据要求由BDD逐项列出，报告结构见[空模板](../acceptance/单实例报告模板.json)。全部产品实例仍NOT_RUN。

## 1. 证据分层与准入

| Gate | 必须提交的证据 | 当前状态 | 失败处理 |

| G2 依赖/原生小样 | 真实安装、frozen lock、Expo匹配、Metro Android bundle、Debug/Release编译及模块小样 | NOT_RUN | 阻断完整页面开发，定位SDK路径/原生版本 |

## 2. 构建清单与复现

正式标识已通过T14确认：名称“计划打卡”、applicationId=`com.xiang.plancheckin`；开发与测试使用`com.xiang.plancheckin.dev`，独立数据目录。正式包长期同签名、versionCode逐次递增；versionName表示面向用户的版本，首版拟为1.0.0/versionCode1，在首个正式构建清单记录。

P1先准备应用清单和原生配置，使用独立Node24.21.0/pnpm10.28.2/JDK17，核对磁盘与NDK27.1.12297006实际需求。真实安装后`expo install --check`，冻结锁文件；prebuild后保存生成配置。后续重现使用`pnpm install --frozen-lockfile`。Gradle只用项目Wrapper；保存`gradlew --version`、`buildEnvironment`与最终AGP/Kotlin/SDK/NDK解析报告。重点验证模板Gradle9.3.1/AGP8.12组合，未编译前不得标原生兼容PASS。

| 检查对象 | 必须核验 |
| --- | --- |
| 源码/清单 | Git提交或工作区快照摘要、应用lockfile SHA-256、工具版本、config plugin源码版本 |
| 最终manifest | 正式包名；minSdk29/targetSdk36；release非debuggable；无延期功能权限；allowBackup=false及两份XML引用 |
| 备份XML | 旧full-backup-content；新cloud-backup/device-transfer两段均排除全部使用域；实际file/SQLite覆盖db/WAL/SHM |
| 二进制 | APK路径/字节数/SHA-256；JS、三份静态字体、图标内置；不含测试Clock、seed入口或远程OTA |
| 签名 | Build Tools apksigner验证成功；记录证书SHA-256及签名方案结果，核对长期证书；不得记录密码/私钥 |
| 依赖/许可 | 安装后的版本树、Expo检查、许可文件、字体OFL；候选与生成锁图差异经过复核 |

签名密钥在仓库外保存，Gradle从安全本机配置读取；不写共享文档或命令行回显，不使用模板debug keystore冒充长期release。配置插件必须可重复生成：第二次prebuild不得丢失备份排除/包名/签名配置。更新不是远程OTA，只通过同包名同签名APK覆盖安装。

## 4. 自动化与数据夹具

Appium3.8.0＋UiAutomator2 8.7.0独立于应用依赖，服务只监听127.0.0.1，AVD按API串行运行。加载现有`resource/scripts`任务环境，一键脚本只控制自身服务及正确AVD，不复用其他设备执行删除/注入。环境Settings烟测只证明控制链路；产品报告必须填写真实appPackage、Activity和APK摘要。

功能边界使用开发包的测试入口：可注入Clock、固定seed、故障点，仅编译进.dev验证变体，入口不出现在产品导航；正式包构建必须排除这些模块。规则单测在独立tsconfig编译后用Node内置node:test；数据库行为必须另在expo-sqlite验证，不以Node/Python替代。

## 5. 兼容矩阵与性能

8组合为API29/36×360/393dp×fontScale1/2。报告须从设备读回实际API、密度/视口和字号，不用脚本参数代替读回。每组覆盖三类创建/确认、日历/筛选、只读/状态变更、Back和键盘；手势/三键导航与TalkBack覆盖均列出实际执行项。真机结果另外列出，不用模拟器替代触觉、厂商迁移或所有无障碍表现。

性能使用**正式签名、非debuggable正式APK**，API36 AVD4核/4GiB、393dp、100%字号，关Metro，无网络依赖。数据集100计划、3年窗口，40固定/40周目标/20一次性；一次性最多一条结果。随机seed固定；数据窗口以测试业务today为终点生成并存清单，不在正式包里注入测试Clock。

大历史数据导入只在可丢弃AOSP验收AVD：P1先验证ADB root与应用私有目录访问；当前API36镜像为userdebug、ro.debuggable=1，但root注入链路尚未实测。应用force-stop、数据库连接关闭后，由测试工具放入已通过schema/不变量检查的夹具库，核对目录/属主/权限，再启动真实正式APK。不得复制正在打开的db或遗留不同夹具的WAL/SHM；重复运行从独立测试快照/清洁夹具恢复。若此链路不成立，先修正测试载入方法，不能在正式应用发布隐藏seed入口，也不能用带测试代码的APK冒充正式性能结果。

冷启动测force-stop后到事实初始化/对账结束、首屏可操作；首次安装另测。使用单调计时，以系统启动时刻与UI-ready原生标记关联，标记只输出时间/技术状态。1次准备不计，10次冷启动；报告原始值、中位数、P95、最大值，P95≤3s。切月/详情各20次，从点击到最新revision呈现且可操作，P95≤1s；首次/缓存分别记录。P95采用nearest-rank（排序后ceil(0.95×n)项），数据计数/分数错误即失败。

## 6. 覆盖升级、故障与交付

升级准备上一版本正式签名APK与已提交样本，保存各表逻辑摘要/行数/固定时区。安装新APK覆盖，不卸载、不清数据；启动执行迁移，核对名称、规则、记录、只读、截止引用和统计一致。至少覆盖：正常升级；待生效事件跨升级后生效；所有待迁移中途失败全部回滚；进程中断重启恢复；更高schema被旧代码阻断。签名不符/包名变更不是合格升级。v1初次交付前可用专用旧schema验证包进行演练，不伪称已有正式旧版。

设备空间不足通过开发验证包故障点与可丢弃AVD验证；记录错误码/原库摘要/重试结果。进程中断分别选commit前、commit后返回前，重启通过最新事实确认是否落库，不恢复草稿或自动重提交；测试调用方仍持有原信封时另验receipt重试。不得把“未收到成功”当成必然未保存。关闭系统备份通过最终APK静态规则及两API行为演练留证；厂商换机行为未经真机测试不能写全厂商PASS。

最终交付目录至少包含APK、SHA256、build-manifest.json、验收报告、性能原始数据、许可、安装/覆盖升级说明。签名私钥及用户数据库不进入交付目录。报告只使用PASS/FAIL/NOT_RUN/BLOCKED，BLOCKED注明具体外部条件，不能把未执行项目默认为PASS。
