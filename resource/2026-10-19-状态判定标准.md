# 需求分析：状态判定标准

阶段：状态抽象草案，仅确定本轮状态的识别与拆分标准，尚未展开完整状态清单、迁移或原子需求。

## 1. 本轮状态的定义

根据 [UI设计还原需求文档](2026-10-17-UI设计还原需求文档.md) 第1、3、5、6节，本轮只有 UI-001，需求与验收均以 UI 设计为依据。

**一个确定的状态，是在已明确的需求范围和观察层级内，对本轮验收而言等价的一组当前界面事实；它有精确来源、可判定的纳入条件，以及与已知相邻状态的区分依据。**

这里的“等价”是指：在对应展示参数下使用同一套视觉判定即可覆盖，不会因合并而丢失资料已经要求分别核对的差异。状态边界由范围内的验收差异决定，画板数量和状态名称均不直接决定边界。

“确定”表示状态的含义和判定边界清楚；不表示该状态已经实现、验收通过或获得本轮人工确认。

状态可用以下结构描述：

> 状态 = 页面／组件范围 + 当前展示模式 + 影响验收的局部状态事实

设计来源、参考尺寸、展示样例和视觉约束随状态记录。其中，名称、日期、数量、备注等样例值可以变化；只有变化影响了本轮的视觉判定义务时，才需要单独记录相应呈现变体。

## 2. 六项判定标准

| 标准 | 必须回答的问题 | 本轮判断方式 |
| --- | --- | --- |
| 有来源 | 这个状态由哪里定义？ | 能定位到需求条款、具体画板及区域；精确样式再引用令牌或设计节点。不能仅凭页面名称、控件存在或常见做法推断。 |
| 有范围 | 描述的是整页、卡片还是控件？ | 明确观察层级。例如“全局日历”是页面场景，“选中日期”是日期格的局部状态。 |
| 有当前事实 | 当前应呈现什么？ | 写明内容结构、选择标识、可见控件、只读呈现或警示等；使用“已选中成功”，不用“点击成功”代替状态。 |
| 有区分边界 | 什么差异足以成为另一状态？ | 在同一范围内，结构、控件呈现、选择样式、结果表达、只读或警示等产生独立视觉核对义务时区分。仅样例内容不同通常不另建状态。 |
| 可独立核对 | 怎样判断展示是否符合？ | 对应画板、区域、逻辑尺寸及视觉检查点明确，能核对布局、文案层级、选中样式等；不要求先完成业务流程。 |
| 无范围外推断 | 是否混入设计没有定义的结论？ | 分开记录已知呈现和未知事项。按钮可见不等于已证明可点击；结果选中不等于记录已保存；只读外观不等于底层修改已被拦截。 |

**以上条件满足，且来源之间没有影响该状态含义的未解决冲突，才能在当前分析层级把它列为“定义清楚的状态”。**

## 3. 状态拆分与合并规则

1. **先确定视觉对齐目标，再决定是否拆分状态。** 需求文档第3节的23个画板是逐页对照基线，画板内已有状态样例是不能遗漏的局部检查点。不能仅因状态名称不同，为同一视觉目标重复建立页面验收场景。
2. **先定层级，再判断差异。** 页面状态、组件状态和示例数据分别记录；不把每个控件的所有组合展开成整页状态。
3. **有不同且可定位的视觉目标才拆分。** 例如结果选中表现、只读呈现、警示面板和不同表单结构，需要有对应的设计区域或明确参数。只有状态名称、业务含义不同，而参考区域、目标表现和检查点相同，本轮应合并。稿中未定义的状态变化，不能自行补齐。
4. **同类样例优先参数化。** 任务名、具体日期、数量和备注内容一般作为展示参数。长文本等若影响排版，可作为视觉对照样例，不自动增加业务状态。
5. **共用规范不增加状态。** 背景色、通用字体、圆角、金属渐变等作为视觉约束引用；改变一个样式参数通常是同一状态的还原差异，不自动成为新状态。
6. **状态存在与状态迁移分别取证。** 两个状态有设计稿，并不能证明它们如何切换。本轮不据此追加业务事件、守卫、保存结果或路由闭环。

### 3.1 多个状态引用同一画板时，对齐什么

**同一画板、同一区域、同一组视觉参数，对齐目标没有区别。** 不能通过换一个状态名称，就把同一目标变成多个不同的视觉要求。

| 对应情况 | 对齐目标 | 分析方式 |
| --- | --- | --- |
| 状态名称不同，但对应区域及目标表现相同 | 同一个视觉目标 | 合并为一个视觉验收场景；业务含义差异不在本轮展开。 |
| 同一画板包含多个已画出的局部样例 | 各样例所在区域已有的布局、文字与样式 | 保留一个画板级对照基线，分别列出区域检查点；局部样例不自动成为多张独立整页设计。 |
| 设计明确给出同一组件的多个替代样式 | 共用外观约束，加上来源明确的局部替代样式 | 分别核对这些组件变体；只有设计明确其组合与位置时，才能据此定义对应整页目标。 |
| 想象中应该不同，但设计未画出且无明确视觉参数 | 没有可确定的新增对齐目标 | 按需求文档第5节，不追加设计；不自行拼接、隐藏、移动现有区域来生成另一张完整页面。 |

因此，本轮首先维护“23个画板级对照目标＋各画板内已有状态样例的区域检查点”。状态名称服务于定位这些目标，不独立增加验收义务。图16的暂停确认卡片与待生效卡片有不同的局部对齐内容，但不能仅据此推导两张完整页面各自的布局。

## 6. 后续每个状态的最小记录

每项记录至少包含：**名称、观察层级与对象、纳入条件、当前事实、与已知相邻状态的区别、来源定位、画板与区域、对齐目标及局部差异、参考尺寸、可变展示参数、视觉判定点、未知或冲突事项**。如果无法写出来源明确的局部差异，就不应仅凭名称把同一个视觉目标拆成不同状态。

资料不足时标记具体缺口；资料冲突时列出双方依据。加载、校验、保存中等未提供视觉稿的内容，按需求文档第5节保持本轮范围外，不自动列为必须补设计的状态。

后续状态清单仍归属于唯一需求 UI-001；状态数量、画板数量和视觉检查点数量，均不直接转换为新增功能需求数量。

## 7. 状态边界的强制准入规则

### 7.1 先固定比较范围

开始识别状态前，先写明本次允许参与区分的验收维度。本轮为界面结构、组件表现、文案层级、选择样式、结果表达、只读呈现、警示等视觉维度。

页面与组件分别建清单；比较两个候选是否等价时，须处于同一观察层级和对象范围。不能拿整页与某个按钮比较，也不能因为同屏有三个不同样式的控件就增加三个整页状态。

本规范中的视觉等价仅适用于当前 UI-001。若后续需求明确纳入业务行为，则允许操作、约束、业务结果或后续能力也可能构成区分依据；届时不能仅凭画板相同合并业务状态。

### 7.2 新增状态必须同时提交四项证据

| 准入项 | 必须写清的内容 | 不通过时如何处理 |
| --- | --- | --- |
| 来源证据 | 精确条款、画板区域或节点；直接推导须列出依据和推导过程，不能引入新的设计选择。 | 仅为惯例或设想的，保持本轮范围外；本轮已要求但缺依据的，登记待决。 |
| 边界条件 | 什么当前事实满足时属于此状态；与哪些已知候选容易混淆，靠哪项事实区分。 | 修改定义；不能只写“正常状态”“异常状态”或一个页面名称。 |
| 差异证据 | 与同层级最接近的现有状态相比，哪项有来源的视觉判定不同，或哪项已要求内容尚无承载。 | 若全部判定等价，合并并保留全部来源；不得靠换名称增加状态。 |
| 对齐证据 | 对应哪个完整画板或局部区域，具体对齐哪些内容，哪些内容只是可变参数。 | 不生成假想的整页效果；局部目标只作为组件样例或区域检查点。 |

第一项状态可以用其承载的明确验收义务建立基线；后续新增必须说明相对于已有清单的覆盖缺口或差异，不能循环引用候选之间的名称来证明拆分必要性。

“区分证据”至少写出一项能够区分目标表现的具体判断。例如，图07选中项要求绿色边框和浅绿底；不能仅写“状态不一样”。没有来源明确的另一种选中表现时，也不能由此自动补出另一张完整页面。

### 7.3 每个候选只选择一种主要归类

| 归类 | 适用条件 |
| --- | --- |
| 页面状态 | 来源定义了可核对的整页场景，且不能由现有同层级状态及其展示参数完整覆盖。 |
| 组件状态／局部样例 | 差异只落在明确组件或局部区域；来源没有定义新的整页组合。记录在所属页面下，不同时重复计为新增页面状态。 |
| 展示参数／视觉约束 | 仅样例值变化，或属于同一目标的字号、颜色、间距等固定要求；直接挂在已有状态或公共规范上。 |
| 合并 | 与已有同层级状态的判定等价；记录归并去向，来源和覆盖义务不能丢失。 |
| 待决 | 当前需求已经提出该义务，但来源冲突或不足以确定它的状态边界、目标表现。 |
| 本轮范围外 | 当前需求未提出或明确排除；不得从常见交互、历史 PRD、实现代码或通用检查清单补入。 |

候选可以同时带展示参数和视觉约束，但其主要承载层级应唯一。“待决”不当作定义清楚的正式状态，也不能继续以其未知结论推导其他状态。

## 8. 用来源覆盖保证完整，用准入审查限制拆分

### 8.1 建立有限的来源覆盖清单

先逐项登记需求文档第3节的23个画板，再登记各画板中已有且需分别核对的局部状态样例，以及第4、6节的相关视觉要求。清单单位是有验收意义的要求或样例，不机械地把设计树的每个节点当成状态。

每个来源项记录：**条款／画板区域、要求的表现、承载页面状态、局部检查点或公共约束、处置结果、未解决问题**。

处置结果只能为：已映射、与已有项合并、经范围条款判断不适用、待决、未分析。合并后仍保留原来源项的映射；不能通过删掉来源项让覆盖看起来完整。

### 8.2 按三个步骤推进

1. **建立基线。** 按来源顺序整理整页场景，先挂接局部样例、展示参数和公共视觉约束；先复用已有定义，只有准入证据充分才新增状态。
2. **双向查漏。** 从来源到状态，检查是否有要求未承载；从状态回到来源，检查是否有无依据或重复的拆分。每个画板只对其实际要求的维度检查，不机械展开失败、权限、返回、时间变化等组合。
3. **修订后复核。** 有变化就重查受影响定义及覆盖关系；最后一次含义或结构变更之后，必须在当前内容上进行一次全量复核，才能报告本阶段收敛。

这套顺序减少重复推演，但不以固定状态数量、固定审查轮数或时间上限替代完整性检查。

### 8.3 参数与组合的限制

- 日期、名称、数量、备注等优先作为参数；只有来源要求不同视觉判定时，才分成相应类别，不枚举所有具体值。
- 独立组件或独立维度分别覆盖已有样例；不自动构造它们的笛卡尔积。
- 只有资料明确要求某种组合，或已有范围内规则直接推出且不需新增设计选择时，才记录组合目标及推导依据。
- 文本长短可能影响排版，可以记录有依据的对照数据；不据此发明稿外布局或新业务状态。
- 来源未规定不等于业务上禁止，只表示不能纳入当前分析的确定结论。

## 9. 可复核的停止条件

满足以下条件时，才能说“在当前来源、范围和观察粒度下，状态分析已经收敛”：

1. 23个画板及本轮条款中的视觉义务均有明确处置，不存在未分析的来源项或遗漏的已有状态样例。
2. 每个保留状态均通过四项准入；每个新增拆分均能指出具体的独立差异或覆盖缺口。
3. 每项局部目标均有所属页面或画板，不能把未定义的局部组合冒充完整页面目标。
4. 同层级等价状态已经合并，展示参数、固定视觉约束未重复计为状态。
5. 最后一次变更后已完成全量复核，没有新的有来源缺口；复核记录能说明已覆盖、合并、待决或不适用的原因。
6. 来源冲突和资料不足如实保留；影响状态定义的待决未解决前，只能报告带缺口的草案，不能宣称全部状态已确定。

“收敛”仅针对当前资料，不是对所有可能业务场景的穷尽证明。出现新来源或范围变化后，重新审查受影响内容，并在修订结束后全量复核。

## 10. 可直接执行的规范条款

> 状态以当前需求范围和固定观察层级内的可验收差异为边界。新增状态须同时具备精确来源、当前纳入条件、相对既有状态的差异或覆盖缺口、可定位的对齐目标。等价候选必须合并；局部差异优先作为组件样例；样例值与固定样式作为参数或约束。不得由常见交互、历史规则、控件组合或状态名称推导新增状态。先维护来源覆盖清单，再执行来源到状态、状态到来源的双向审查；在全部范围内义务均有处置、无未审项、无无依据拆分，并完成最后一次变更后的全量复核后，方可报告收敛。待决不得冒充确定结论，状态拆分不得自动增加功能需求。
