# 计划打卡 Android V1｜设计需求文档

> 日期：2026-10-09（Asia/Shanghai）  
> 平台与技术：Android、React Native/Expo  
> 首版范围：个人核心闭环、免登录、本机保存、仅文字备注  
> 交付目标：Windows 模拟器实际验证＋无需开发服务器的独立 APK  
> 当前阶段：自包含需求与全新 pen.dev UI/UX；应用实现尚未开始

## 1. 定位与目标

帮助个人知道今天有哪些计划，主动记录实际结果，再通过日历和统计回顾。体验像安静的个人执行记录簿，不用排名、勋章或焦虑催促。

核心闭环：创建计划 → 今日查看 → 主动申报结果 → 日历/详情回顾 → 继续执行。

安装即可使用，不需要手机号、账号、后端、网络或通知权限。无计划时进入今日空态并创建；独立 APK 在飞行模式和关闭开发服务器时也完整运行。

本文与 [UI/UX 规格](UIUX-计划打卡-Android-v1.md)、[设计令牌](design/design-tokens.json)、[页面清单](design/page-map.json)构成独立规格，所有内容均在本目录内维护。

## 3. 计划与日期规则

### 3.1 时间规则

| 类型 | 输入 | 执行与判定 |
| --- | --- | --- |
| 固定日期循环 | 开始、可选结束、至少一个星期 | 有效期内选中日可记录；每日为七天全选 |
| 每周目标 N 天 | 开始、可选结束、N 为 1–7 | 自选日期记录，以成功天数判断周目标 |
| 一次性任务 | 今天或未来的截止日期 | 待完成、逾期、按时完成、迟完成、失败、取消 |

开始/结束包含当日；结束不得早于开始。自然周为周一至周日。

创建时保存设备对应的 IANA 时区。业务日期、自然周与截止均按计划时区计算；创建后固定，设备换时区不能移动历史记录。有歧义时显示绝对日期与时区。

### 3.2 方向

要做的成功表示本人确认完成；不要做的成功表示本人确认目标行为没有发生。失败也须本人申报，未打开应用或未提交结果不能自动变成成功/失败。

不要做允许当天提前确认；后来发生该行为须修正为失败，保留已修正标记。

### 3.3 创建字段

| 字段 | 规则 |
| --- | --- |
| 名称 | 必填，去除首尾空白；上限 80 字符 |
| 方向 | 循环要做/不要做；一次性固定要做 |
| 时间规则 | 三选一，只出现对应字段 |
| 固定星期 | 至少一个；提供每日快捷项 |
| 每周目标 | 整数 1–7 |
| 开始日期 | 循环默认今天，按合法业务日期保存 |
| 结束日期 | 循环可选，不早于开始 |
| 截止日期 | 一次性必填，不早于今天 |
| 说明 | 可选，上限 1000 字符 |
| 时区 | 自动保存，只读展示 |

文字长度、结果与日期语义均在本版固定；不因平台变化改写业务规则。

保存前校验，错误贴近字段并可朗读。保存中防重复，失败保留输入；成功后计划即时进入列表和对应今日分区。

### 3.4 生命周期与编辑

运行中生成应执行日期；暂停不产生新应执行日；恢复继续；归档停止执行但保留历史；删除永久移除计划和记录。

名称、说明可修改。方向、类型、时区、既定开始日期首版不可修改；改变这些属性通过新建计划完成。

星期、目标或结束日期修改保存规则版本，次日起生效；历史继续按当时规则解释。编辑确认说明生效日期与历史保留方式。

周目标周中开始、结束、暂停、恢复或修改目标，当前周为部分周：保留记录，不计周达标率与连续达标周数，下一完整周重新考核。

暂停/归档说明影响；删除明确全部历史将永久删除，提供归档替代。不能通过滑动即删除。

## 4. 打卡、补记与修正

循环结果为成功、失败、跳过，文字备注可选，上限 2000 字符。没有备注也可提交。

同一计划同一业务日期最多一条有效记录。重复打开进入修改，重试不产生第二条，不把同一天算成多个成功日。

保存计划 ID、业务日期、结果、备注、实际提交时间、最近修订时间、补记/已修正标记；保留必要的结果与备注修订历史。

| 状态 | 语义 |
| --- | --- |
| 待处理 | 当前有效固定日尚未提交 |
| 成功 | 本人主动确认做到 |
| 失败 | 本人主动确认未做到 |
| 跳过 | 本人主动不参与本次考核 |
| 未记录 | 已结束固定应执行日未提交 |
| 空白 | 非固定执行日或周目标未选记录日，不是失败 |

补记仅限过去且已生效、可记录日期；未来、生效前和固定非选中日禁止。补记同时展示业务日期与提交时间；修改展示已修正和最近修改时间。

一次性截止后未终结为逾期，仍留在今日。完成区分按时/迟完成；失败/取消为终态。误操作修正原记录，真正重新尝试则新建任务。不套用循环每日完成率。

## 5. 今日、日历与统计

今日分固定待处理、本周可记录、截止事项和已记录。周目标不是每天必须完成，逾期任务保留；保存后原卡片反馈，不突然消失。

月历七列，日期状态用形状、颜色和文字共同解释。选日显示记录，合法空日期可补记；周目标空白无未记录。全局与单计划使用同一日期/结果模型。

固定完成率＝成功次数÷（已结束应执行次数−跳过次数）。今日未提交不进入分母，提交后进入；分母为零写暂无可计算记录。显示分子/分母与截止日。

固定计划显示连续成功次数；只有七天全选可称连续天数。失败、跳过、未记录中断。周目标按完整周判断达标，周未结束不提前失败，超额可显示 4/3，达标率最高 100%；部分周不参与连续达标。

一次性显示截止、结果、完成时间，不计算每日完成率或连续打卡。详情展示时区、统计截止日、历史结果、备注和补记/修正标签。

## 6. 本机实现约束

建议本目录建立独立 Expo 客户端，领域规则、类型、组件和设计资产均放在目录内，不引用其他项目或服务。

SQLite 为唯一权威数据源。计划、规则版本、生命周期和记录可靠落盘；关联更新使用事务，落盘后才反馈成功；唯一性约束保障同日幂等。升级迁移失败保留原库，不能悄悄清库。

工程建议使用 SQLCipher 与 Android SecureStore/Keystore。Expo SQLite 支持 Android SQLCipher，但必须在原生构建和 APK 实际启用验证。[Expo SQLite](https://docs.expo.dev/versions/latest/sdk/sqlite/)

系统自动备份/恢复不等于可恢复加密记录；数据库与密钥生命周期一起验证，明确排除不匹配的系统备份，首版不提供恢复承诺。[Expo SecureStore](https://docs.expo.dev/versions/latest/sdk/securestore/)

核心数据不依赖账号、token、远程时钟、API、推送或同步队列。最终 APK 内置 JS、字体和必要资源。依赖版本、SDK/JDK/Gradle、包名与签名在实现准备时按稳定工具链核对并固定。
