## 2. AI如何执行验收

已配置路线为AI通过终端编排ADB与Appium3/UiAutomator2：启动/安装/重启由ADB完成，Appium按元素定位操作并取得界面树与截图，测试用例负责明确断言，AI整理失败证据及视觉对照。UiAutomator2官方支持Windows宿主与安卓模拟器；其API26+支持范围包含本项目API29/36，且本机两套系统已实测连接。[Appium驱动要求](https://github.com/appium/appium-uiautomator2-driver)

当前会话具备终端与本地图片查看能力，原生桌面GUI控制API未启用；ADB/Appium接口已在专用无窗口AVD完成实际操作，不依赖鼠标操作模拟器的Windows外框。后续可重新建立连接执行应用测试。

Appium3.8.0/UiAutomator2 8.7.0已独立安装，未新增到应用候选锁文件，也不进入APK运行依赖；独立Node24.21.0/npm11.19.0满足环境要求。[Appium基础要求](https://appium.io/docs/en/latest/quickstart/requirements/)

| 验收内容 | 自动化方式及证据 |
| --- | --- |
| 创建、确认打卡、筛选、查看记录 | 元素定位＋字段输入＋结果/只读权限断言；稳定定位标识在实现时设计 |
| 日历显示、状态色、边距、字号 | 固定数据/尺寸/字号的截图与Pen对应区域核对；记录视觉问题 |
| 重启和本机持久化 | 重启应用后检查原记录和统计；测试库与日常数据分离 |
| 独立APK | 关闭Metro、断网启动及完整核心操作；记录安装包版本/证书 |
| 历史日期、跨日、暂停阶段、统计 | 受控测试数据/Clock及原生集成用例共同验证，不能仅凭截图认定算法正确 |
| 性能 | 沿用技术文档release测量流程，不能把AI或Appium操作耗时当作应用响应时间 |

截图必须统一视口、字号、数据与字体，并对齐设计对应区域；完整长画板与手机单屏不直接做整图像素相等判定。AI完成点击或给出视觉评价也不等于全部AT验收通过；每条保存期望/实际、断言、截图/日志及PASS/FAIL/NOT_RUN。
